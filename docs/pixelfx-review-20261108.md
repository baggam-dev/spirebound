# pixelfx 활용 및 이펙트 전반 개선 검토 — 2026-11-08

## 결론과 검토 범위
활용 가치 높음. 기존 전투 렌더를 교체하기보다 효과의 시간별 형태·색 변화·파편 소멸을 참고하고 필요한 효과만 선별 도입하는 방향을 권장한다. 이번 요청은 검토이며 설치/실행/실제 시안 생성/런타임·배포 자산 수정은 하지 않았다. 아래 평가는 소스 정적 분석이며 실제 움직임·성능을 검증한 결론이 아니다.

## 공식 자료에서 확인한 점
- 공식 README: 244개/21분류, JS 효과, 팔레트·방향 변경, 투명 PNG 시트/JSON 내보내기 지원. Claude Code 플러그인은 저작 보조이며 게임 실행의 필수 의존성이 아니다. 이번에 설치하지 않음.
- core/fx.js: CanvasRenderingContext2D에 직접 그리는 API가 아니다. color/light Uint32Array 버퍼와 Painter를 사용하며 composite는 프레임 전체 픽셀을 순회한다. 시뮬레이션 효과는 update(dt)를 120Hz 이상 세부 단계로 나눈다. 따라서 '짧은 코드/이미지 없음'이 가벼운 실행을 보장하지 않는다.
- sword-slash: 약 0.06초에 주 타격이 도착하고 밝은 초승달/내측 잔상/불꽃이 시간차로 사라지는 구조. 기본 효과 지속 0.75초, 별도 act에는 준비·회수와 hit-stop 정보가 있다. 이 시간들을 Spirebound에 그대로 적용하면 기존 공격 타이밍과 달라질 수 있다.
- MIT 코드/효과는 상업 이용·수정 가능하나 사용분의 저작권·허가문 보존 필요. NOTICE의 Sprite Fusion/Hollow Crown 출처도 사용분에 맞게 유지. gallery/fonts의 Patch Pixel은 MIT 범위 밖이므로 가져오지 않는다.
- 몸에 붙는 일부 효과는 기본 더미 신체를 그린다. 자체 캐릭터 마스크/좌표로 재작성하거나 제외해야 한다. moves/act 전체를 가져오지 않는다.

## 현재 구현과 겹치는 점
- src/rendering/skill-visuals.js: 이미 화염/냉기/독/연쇄/정밀 색과 레벨별 화살 잔상 존재. 새 원소 체계를 만들 필요 없음.
- element-hit-visuals.js: 방향성 원소 피격, 수명 .22~.4초, 최대48개 제한. arrow-impact-visuals.js: 일반/정밀 피격 .2초·최대24개. 기존 이벤트를 유지하고 시각 프로필만 개선할 지점이다.
- skill-burst-art.js: 다층 픽셀 화염/냉기/독/전기 형태와 폭발 구현. 단순 원을 처음 대체하는 작업으로 설명하면 중복이다.
- ground-visuals.js: 아군 장판 빈 중앙·낮은 농도, 적 필드 별도 처리·반경 clip 및 reduced 연결 존재.
- frost-aura.js: 몸PNG와 분리된 연무/6입자·동결정지·효과줄이기 존재. 새 오라 시스템 대신 질감/끝맺음만 보강 후보.
- game.js: 아군FX 뒤 적 위협 경계/보스 경계 재표시, 적탄 최상단 단일 표시, 전투 라벨 분리. 새효과도 이 우선순위를 따라야 한다.
- 운영0.49/이전 QA 결과는 기존 문서상 상태다. 이번 공개 서버 확인이나 성능 측정은 하지 않음.

## 연결 방식 비교와 권장
1. 기본 권장: 작은 효과들의 형태/시간 곡선을 기존 Canvas 렌더에 이식. 기존 이벤트·elapsed·수명·reduced와 자연스럽게 연결되고 부가 엔진이 없다. 실제 코드 차용 시 MIT 고지 유지.
2. 복잡한 불꽃/파편만 사전 시트화하여 기존 drawImage 경로로 재생하는 혼합 방식. 런타임 픽셀 시뮬레이션 비용을 피하는 대신 다운로드/디코딩 메모리·팔레트별 변형 비용 발생. pivot/alpha/앞뒤 레이어를 보존하고 기본 더미가 들어간 프레임 제외. 작은 수의 공유 atlas·온디맨드 로딩/실패 fallback 검토.
3. 직접 createFx 연결은 제한적 실험 후보. 작은 오프스크린 버퍼를 재사용하고 composite→오프스크린 putImageData→메인 drawImage로 합성해야 한다. 메인 Canvas에 예제처럼 putImageData하면 기존 그림을 덮거나 transform/globalAlpha/clip 기대와 달라질 수 있다. 전체화면·효과마다 새 버퍼 생성·대량120Hz 시뮬레이션은 기본안에서 제외.

최종 권장: 1을 중심으로 2를 선택적으로 사용. 라이브러리 전체 설치/244개 일괄 이식은 이점보다 통합 범위가 크다. 소스 참고 방식으로도 적용 가능하며 Claude 전용 기능에 종속될 필요 없다.

## 공통 설계 기준
- 실제 명중 이벤트·현재 공격 시간에 동기화. 예고/유효피해/장식잔류를 분리하고 피해가 끝난 뒤 효과가 새 위험범위처럼 보이지 않게 한다.
- 강한 핵·중간 몸체·어두운 꼬리의 밝기 단계, 짧은 타격과 느린 소멸의 대비를 통일하되 현재 원소색·몸체PNG를 유지한다.
- 적 예고선/활성 경계·적탄·라벨 우선순위 보존. 아군 효과를 늘려 기존0.48/0.49 가독성 개선을 되돌리지 않는다.
- 효과줄이기는 핵심 순간 표시/상태 구별을 남기고 입자·잔상·큰 glow를 먼저 제거. 일반/치명/원소 조합의 중복도 제한.
- 기존48원소/24화살 상한을 무작정 늘리지 않는다. 전체 동시효과·화면 점유·장판 중첩의 예산은 향후 실제 장면에서 확정한다.
- 시각 전용 seed/시간 사용, 전투 RNG/저장/피해/범위/탄수/공격 주기를 건드리지 않는다. 일시정지·동결·재개에서 장식만 계속 움직이거나 옛타격을 재생하지 않게 한다.

### 구현 공통 규칙과 검증 기준
- 기존 Canvas에 필요한 형태/시간 곡선만 이식하는 방식이 기본이다. 복잡한 불꽃/파편은 선택적으로 작은 시트를 사용하고 실패 시 기존 렌더로 돌아간다. 시트가 필요 없는 단계에 새 자산 로더를 먼저 만들지 않는다.
- 시각 전용 공통 함수는 실제 중복이 확인되는 범위만 추출한다. 전투 RNG/판정/저장 필드에 시각 상태를 추가하지 않는다. 효과마다 새 버퍼를 만들거나 244개 전체를 연결하지 않는다.
- 단계2 이후 '구현 완료'는 실행 검증을 뜻하지 않는다. 배포 지시 전에는 테스트/구문실행/서버/브라우저 QA도 실행하지 않으며 정적 소스·diff 대조까지만 한다.
- 배포 시 현재판과 동일한 장면/해상도/옵션으로 비교한다. 평균/p95 프레임·동시효과 수·메모리/자산 크기를 기록하고 악화가 나타나면 입자/잔상/시트 크기를 줄인 후 재측정한다. 측정 전 고정 FPS 보장은 하지 않는다.
- 위협 경계가 효과 뒤에 묻히거나 기본/완화에서 원소·상태 구분이 사라지는 경우 완료로 처리하지 않는다. 일반/치명/원소 중복 명중과 여러 장판의 겹침을 필수 비교한다.
- MIT 코드 사용분 저작권/허가문 및 해당 출처 유지. Patch Pixel 폰트·기본 더미 신체·act 전체 hit-stop은 포함하지 않는다.
