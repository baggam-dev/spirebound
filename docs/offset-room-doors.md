# 승인 중앙 외 문 위치

2026-10-13 door-position-v1 시안 승인 ‘좋아 진행’. 코드·문서·로컬 커밋만, 테스트/브라우저 QA/푸시/배포하지 않았다.

## 구현

- doors.js가 연결마다 문 중앙 좌표를 하나 선택해 두 방의 반대 방향 doorPositions에 같은 숫자로 기록한다. 벽 유효 구간 x25~935/y44~508의30/40/50/60/70% 후보를 사용한다. 코너 제외, 방 상호작용 오브젝트/상자에 가까운 후보를 배제한다. 시드/층별 독립 RNG이므로 전투 RNG를 소비하지 않는다.
- room-layout 갱신에서 신·기존 원정 모두 문 배치를 적용한다. doorLayoutVersion1은 중복 재생성을 막는 표식이다. 현재 generation34·랭킹 버전 유지, 구버전 원정 지도 보존 분기 없음.
- simulation 출입 축 정렬은 해당 문 좌표를 사용한다. 방 전환 시 반대편 문 중앙의 안전 진입점(x48/912 또는 y63/477)으로 들어간다. 문 너비/통과 허용 폭은 기존80/70px를 유지한다.
- game 문 틈/문틀/잠금 표현과 interaction-visuals의 출구 개방 이펙트도 같은 좌표를 사용한다. 바깥 돌벽은 기존 표면을 그리고 실제 문 틈을 새 위치에서 덮어 그리는 기존 방식 유지. 미니맵의 문 표시도 변동 위치 비율을 반영한다.
- 실제 열린 문 앞 보호영역(상하180×125, 좌우155×150)에서 props는 제거하고 내부벽은 영역을 잘라낸다. 조각이 저장 한도30개를 넘으면 보호영역에 걸친 장애물 자체를 제거한다. 기존 좁은 통로를 새 문 앞에 남겨놓지 않도록 한다. 본래 중앙 장애물의 이동 경로/전체 연결성은 배포 전 확인이 필요하다.
- object-positions의 문 주변 회피 기준을 실제 doorArrival로 연결했다. 처음 원정 생성 시 오브젝트는 문 배치보다 먼저 생성되므로 후보 선택에서 이미 생성된 오브젝트와 충돌을 피한다.
- storage는 doorLayoutVersion 및 연결별 문짝 좌표 범위/일치를 검증한다. 새 문 저장을 다시 불러와도 재선택하지 않는다. 현재 플레이어 겹침은 기존 recoverPlayerPosition으로 처리한다.
- 최종10층 전용 악마 두 방 연결은 중앙 문 유지/진입부 장애물 갱신 제외: 기존 악마 위험물/전용 공간의 규칙을 바꾸지 않는다. 점멸은 기존 방안 경계 제한을 유지하고 문을 뛰어넘어 다른 방으로 순간 이동시키지 않는다.
