# 전면 비주얼 개선 검토 (2026-09-30)

사용자 의견: 출시 제품 수준을 위해 캐릭터 디자인, 던전 질감, 스킬 이펙트 전반의 큰 폭 개선이 필요하다. 이 문서는 **검토안**이며 런타임 구현·배포는 시작하지 않았다.

## 판단과 현재 구조
- 전면 개선에 동의한다. 현재 영웅·몬스터·보스·벽·장판·공격 대부분이 Canvas 코드 도형으로 그려지고, 정적 이미지 자산은 타이틀 아트 중심이다. 부분별 디테일은 늘었지만 통일된 원화/팔레트·재질·조명·애니메이션 규칙이 없어 요소들이 별개로 보일 위험이 있다.
- 이미 개선한 내·외벽 공통 패턴과 벽 이미지 캐시, 전투 예고와 실제 판정의 일치, 저장/충돌은 유지한다. 스프라이트·타일셋으로 교체하더라도 게임 로직과 시각 계층을 분리한다. 타이틀 이미지와 인게임 픽셀 아트의 인상도 함께 맞춘다.
- 권장 방향: **어두운 성채 판타지 픽셀 아트**. 영웅/적은 읽히는 실루엣과 두세 단계의 재질 명암, 던전은 낮은 채도·대비, 공격과 보상은 제한된 고채도 색을 쓴다. 금발 영웅의 밝은 머리와 활, 층별 보스의 형태가 작은 모바일 화면에서도 먼저 보여야 한다. 화려한 스킬이 위험 예고·안전 공간·투사체 방향을 덮지 않게 한다.

## 권장 작업 순서
1. **아트 디렉션 확정:** 960×540 원본/PC/모바일 캡처를 모아 지금 화면의 문제를 표시한다. 영웅·일반몹·보스의 실루엣, 바닥/벽/문 재질, 기본/속성 공격, UI에 공통 색·빛 방향·픽셀 크기·윤곽선/그림자 규칙을 정한다. 동일 장면의 서로 다른 방향 시안 2~3개로 비교하고 하나를 고른다.
2. **세로 조각(vertical slice):** 1층 일반방+2층 첫 보스에 영웅의 정지/보행/활쏘기/피격, 적 2종, 외곽/내부 벽·바닥·문, 화염/서리/독/번개 화살 및 장판 1종, 핵심 HUD를 함께 적용한다. 이 단계에서 도형 그림을 전부 폐기하지 말고 필요한 캐릭터/타일은 스프라이트로, 절차적 장판·탄환은 코드 이펙트로 유지하는 혼합 방식을 비교한다.
3. **게임 전체 확장:** 선택한 규칙을 층별 소재/조명과 몬스터 계열·보스 페이즈·유물/스킬 시각에 확장한다. 보스/스킬마다 '준비→발동→피격→소멸' 프레임을 갖추되 실제 판정과 위험 표시를 계속 일치시킨다. UI·타이틀·결과 화면에도 같은 문자/아이콘/색 체계를 적용한다.
4. **가독성·성능 판정:** 같은 시드·장면을 변경 전후로 PC/모바일 실기기에서 비교한다. 적/플레이어/위험 영역 식별, 공격 방향, 스킬별 색 구분, 저장/일시정지/고정 프레임 안정성과 전체 프레임 p95/p99를 확인한다. 장식 때문에 전투가 안 보이거나 기존 벽 캐시 이점을 잃으면 해당 레이어를 줄인다.

## 첫 단계의 승인 기준
- 먼저 **전체 화면을 한 번에 다시 그리지 않는다**. 대표 장면의 2~3개 시안과 세로 조각을 사용자가 비교할 수 있는 형태로 만든 뒤, 선택한 방향으로 대량 자산 작업을 진행한다.
- 비주얼 변경은 기존 충돌·보스 패턴·랭킹 점수·저장 구조를 바꾸지 않는다. PC/모바일 캡처, 실제 기기 가독성, 기존 게임 QA를 통과한 단위로 커밋/배포한다.
- 웹 Canvas에서 픽셀 자산을 확대할 때 스무딩을 끄고, 반복 타일·정적 장식은 미리 렌더링/캐시한다. [MDN 픽셀 확대](https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/imageSmoothingEnabled), [MDN Canvas 최적화](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API/Tutorial/Optimizing_canvas).
