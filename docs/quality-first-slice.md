# 재미 우선 첫 단위: 빌드 조합 감사와 선택 정보 — 2026-10-06

사용자 목표는 플레이의 재미를 먼저 높이고, 그다음 디자인의 유려함을 높이는 것이다. 레퍼런스 `quality-reference-direction.md`의 첫 실행 단위를 작은 범위로 잡았다.

## 현재 코드에서 확인한 사실

- 메인 5종: 화염·서리·독·번개·정밀. 일반 지원 10종 중 갈래/관통/연속/추적 등은 발사체의 행동을 바꾸지만, `power`/`haste` 등은 주로 수치다. 정밀은 같은 적 연속 타격, 서리는 빙결/파편, 독은 중첩/가스, 번개는 전이, 화염은 폭발/장판으로 핵심 루프가 구별된다.
- 유물 32종 중 `stats` 숫자 합산으로 구현된 유물이 22종이다. 나머지에는 조건부 직격(`lens`/`hunter`/`execution`), 처치 회복(`windSeal`), 유니크 독립 행동 등이 있다. 22종이 모두 무의미하다는 뜻은 아니며, 선택 경험에서 수치 보상 비중이 크다는 근거다.
- 명시적 기술 조합은 셋: `갈래+관통`은 피해 +3으로 숫자 변화, `화염+연속`은 후속탄의 작은 폭발로 행동 변화, `번개+공속`은 전이 거리/비율 변화. 따라서 새 아이템을 대량 추가하기보다 기존 선택의 조합 효과와 발현 빈도를 먼저 검증해야 한다.
- 기존 레벨업 카드는 모든 관련 조합의 **이름·재료만** 나열했다. 후보를 고르면 어떤 효과가 생기는지, 이번 선택으로 바로 완성되는지 알아보기 어려웠다.

## 이번 구현

- 현재 빌드의 다른 재료를 이미 가졌을 때만 해당 후보에 `선택 시 조합 완성` 또는 `활성 조합`과 실제 효과 설명을 표시한다. 아직 관계없는 먼 조합은 카드에서 숨겨 혼잡을 줄였다. 조합 자체·발동 타이밍·수치·저장·랭킹 시즌은 바꾸지 않았다.
- 새로운 효과가 재미를 높였다고 주장하지 않는다. 이 단위는 **조합을 발견하고 선택할 이유를 이해하게 하는 정보 개선**이다. 다음 전투 변화 실험을 설계할 때는 기존 5메인 빌드와 유물의 동일 시드 일반방/보스 시간, 적중 대상·투사체 수·사망 원인을 비교한다. 자동 지표와 별개로 사람의 재도전 의사를 확인해야 한다.

## 다음 재미 후보와 디자인 기준선

1. 우선 `갈래+관통`의 순수 +3 조합과 숫자형 유물의 우선순위를 검토한다. 후보는 단순 더 높은 피해가 아니라 벽·적 배치에 따라 화살 경로/목표 선택이 달라지는 상호작용이다. 현재 자동 조준·전투 예고·보스 방어를 깨지 않는 범위에서 설계하고, 점수 규칙이 바뀌면 새 시즌을 분리한다.
2. 디자인은 1층 일반방+2층 첫 보스의 같은 화면에서 플레이어/적 실루엣, 벽·바닥 마모, 사격→명중→피격 박자와 HUD 정보 밀도를 비교한다. 현 `room-backdrops.js`는 층별 부조/낮은 대비 디테일을 이미 갖고 있어 장식을 단순 증량하지 않는다. 첫 수정은 명암·픽셀 크기·조명·피격 연출의 **통일성**을 겨냥한다.

## 디자인 기준 화면 (수정 전)

- 1층 일반방: [PC](quality-baseline/room1-pc.png) / [모바일 가로](quality-baseline/room1-mobile.png). 외벽·바닥의 저채도 질감은 일치하고 적/영웅은 구분된다. 다만 큰 중앙 바닥은 시각적 변화가 적고, 적의 세부 재질은 실제 게임 크기에서 잘 읽히지 않는다.
- 2층 첫 보스: [PC](quality-baseline/boss2-pc.png) / [모바일 가로](quality-baseline/boss2-mobile.png). 보스의 투구/망치와 영웅의 금발·활이 실루엣으로 구분되나, 모바일 가로에서는 둘 다 작고 우측 수치·미니맵 글자는 매우 작다. 위협 예고·타격 순간은 정지 장면만으로 판정하지 않았다.
- 네 캡처는 시드419, PC1280×800/모바일 에뮬레이션844×390에서 게임 렌더링을 사용했다. QA `tools/qa/quality-baseline-qa.mjs` 오류/가로 넘침0. 실제 기기 가독성이나 디자인 개선 후 비교 결과가 아니다.

검증: 관련 Node 테스트와 Edge PC/모바일 가로 선택 카드 QA, 전체 `node --test` 결과를 WORK_STATUS.md에 기록한다. 실제 플레이 재미/실기기 가독성은 이 검증으로 완료 처리하지 않는다.
