# 치명타 공통 구조 — 2026-11-20

1단계는 로컬 구현/JS 검증 완료. 전용 그래픽·음향·스탯 화면은 2단계이며, 전체 패키지 완료 후 일괄 배포한다.

## 판정과 피해

- 기본 확률 5%, 피해 배율 150%. 유효 상한은 확률 50%, 배율 250%다. 원시 성장 수치와 유효 상한을 구분한다.
- `src/combat/critical.js`의 `applyPlayerDamage`가 방어 보정·치명 배율·HP 변경·실제 감소량 통계를 처리한다. 이미 방어를 계산한 호출은 `defended:true`를 명시한다. 기존 전체 DPS 집계는 각 호출자가 유지한다.
- 같은 평타의 물리/직격 속성은 대상별 packet을 공유한다. 화살비는 장식 화살이 아닌 실제 6회 피해마다 대상별로 판정한다. 빗나감·0 피해·완전 차단은 판정하지 않는다.
- 화상·독·장판·전이 피해는 적용 시 snapshot을 유지하며 매 틱 다시 굴리지 않는다. 일반/치명 화상 누적은 component로 나누고 방어는 합산 피해에 한 번 적용한다. 실제 초과 피해는 남은 HP까지만 집계한다.
- 석궁·요정 탄환·발도/지뢰 등은 설치/발사/시전 시 치명 스탯을 보존한다. 이후 플레이어 성장으로 기존 소환체 수치가 소급 변경되지 않는다.

## 저장과 후속 인터페이스

`migrateCriticalCombat`은 옛 저장에 기본 스탯·독립 난수를 채우고 옛 소환체/무기에도 기본 프로필을 지정한다. `critical-save.js`는 스탯·난수·통계·snapshot·혼합 화상과 동일 ID 충돌을 검사한다. 저장 무기 허용 필드에도 치명 스탯을 포함했다.

`step` 결과의 `damageResults`는 실제 피해 결과다. `attackId/attackIds`, `critical`, `damage/criticalDamage`, `newHit`, `procDepth/procEligible`를 제공한다. 정밀 약점 효과에도 같은 공격 ID를 붙여 2단계에서 복합 명중을 식별할 수 있다. 파생 피해는 깊이 1로 표시하며 새 2차 발동을 허용하는 기준은 깊이 0의 새 명중이다. 결과 큐는 메모리에 최대 256개이며 저장하지 않는다. 통계/HP는 큐 한도와 무관하다. snapshot당 대상 한도는 128이다.

## 2단계 연출 연결 — 2026-11-20

`rendering/critical-feedback.js`가 실제 새 치명 명중을 표시한다. 사망 후 적 배열에서 제거되어도 접점이 남도록 피해 결과가 당시 좌표를 보존한다. 같은 공격 ID의 약점 강화는 `약점 치명!`으로 통합하고 기존 약점 접점은 이때 그리지 않는다. 프레임 신규 6개·활성 12개를 상한으로 두고, 지속 틱은 `newHit:false`이므로 문구/음향을 반복하지 않는다. 금빛 접점은 strength 2이며 완화 모드는 파편 수를 줄인다. 화면 전체 섬광·히트스톱·적 움찔 모션은 추가하지 않는다.

게임 루프에서 `stepRun` 직후 결과를 효과에 합친 뒤 오디오/그리기로 전달한다. `criticalHit`은 더 이상 정밀 음향 별칭이 아니며 contact 그룹 우선순위 4·0.18초 간격의 별도 음색이다. 한 프레임 복합 명중도 가장 강한 접점 큐 하나를 고르고 경고 음향/12음 동시발음 제한을 유지한다. HUD는 `criticalStats`의 유효 확률/배율을 표시한다.

관련 65/65 통과: 실제 치명/지속 틱 제외·동일 공격 통합·밀집 상한·치명 처치 좌표·Canvas 일반/완화 호출·스탯 상한/기본값과 기존 음향/레이어링/접점 회귀. `node --check src/game/game.js` 통과. 증거는 `qa-critical-feedback-20261120/related.log`. 실제 화면/청취 검증은 최종 누적 QA까지 남아 있으며 시각 품질 완료로 단정하지 않는다. 이후 3단계 스킬, 4단계 유물에서 성장 수치를 연결한다.
