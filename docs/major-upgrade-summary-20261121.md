# Spirebound 대규모 개선 구현 요약보고서

작성일: 2026-11-21 · 코드 기준: `49ee9f9` · 대상: 2026-11-20 플레이 후기 이후 누적 개선

## 현재 결론

화살비 조정, 확률 치명타 기반, 스킬6종·유물4종, 신규 조우·적·기관, 대표 성소/하강 바닥 및 전투 연출을 **로컬 구현·커밋**했다. 전체 릴리스의 통합 검증과 배포는 아직 남아 있다.

마지막 JS 전체 회귀 성공은 소환·회복형 지원 적 단계의 **853/853**이다. 이후 기관·맵·바닥 무늬·근접병/궁수 동작·궁극기/요정 변경은 테스트와 화면 QA를 실행하지 않았으므로, 현재 코드 전체가 통과했다고 볼 수 없다. 지금까지의 테스트 수와 시안 승인은 실전 밸런스·배포 성공을 의미하지 않는다.

운영 마지막 확인 기준은 **0.57.0-prebeta / runtime `4660a70`**이다. 이번 요약 작성 중 운영 서비스·원격 상태를 새로 조회하지 않았다. 이 보고서의 신규 개선을 운영 반영 완료로 해석하면 안 된다.

## 2. 전투·성장 변경

### 화살비

회당 계수를7배에서5배로 낮췄다. 6회 전부 적중할 때 보정 전 합계는42배→30배로 약28.6% 감소한다. 반경·회수·간격을 동시에 줄이지 않았다. 기존 진행 중 저장의 화살비 피해는 보존하고 새 시전부터 새 계수를 사용한다. 치명타·왕의 선고·유물까지 조합한 최종 기대 피해는 아직 실전 비교 전이다.

### 공통 치명타

기본 확률5%, 피해 배율150%; 유효 상한은 확률50%, 배율250%다. 기존 정밀 사격의 확정 약점 강화와 확률 치명타를 구분했다. 직접/광역·다단/지속·소환·파생 피해의 중복 판정을 제어하고, 소환 스냅샷과 지속 피해의 결과 계승 규칙을 연결했다.

치명 난수는 지도·AI·성장 제안 난수와 분리해 저장한다. 명중 결과를 시각·음향·통계가 같이 읽도록 했으며, 일반/약점/치명/복합 접점과 스탯 표시를 구분했다. 반복 시각·음향 예산은 실제 피해 판정을 생략하지 않는다.

조우는 보스/계단/시설/입장/관문 등과 겹치지 않도록 제외 규칙과 저장 계획을 갖춘다. 기관 방에는 하강 추적자·지원 조우를 추가하지 않는다. 지원 시전은 누적 피해·빙결/빈틈·대상/시야 상실로 중단할 수 있다.

Pursuer는 전용12프레임, 지원 적/수호체는9/9/8프레임 몸체 자산을 제작했다. 유랑 정예는 기존 근접병 변형이며 독립 신규 몸체 제작 완료로 세지 않는다. 기관은 적 배열과 별도의 방 장치로 구현해 몬스터 치유/처치 수/랭킹 예산과 분리했다. 기관은 **평타 파괴가 아닌 근접 정지 해제 방식**이며, 해제 상태는 하강·재입장에도 유지된다.

상세: [특수 조우](special-encounters.md), [Pursuer](pursuer.md), [지원 적](support-casters.md), [봉인 기관](seal-engines.md).

## 4. 비주얼 개선

**맵:** 대표 성소 바닥을 청회색, 벽을 밝은 상아 회색으로 나눴다. 황동 코너와 실제 문 위치의 문턱을 연결했다. 하강은 붉은 전면색 대신 차가운 저농도 음영과 가장자리 봉인 균열을 사용한다. 모든 층의 원화를 전면 재제작한 작업은 아니다.

**바닥 무늬:** 얼룩·물웅덩이·혈흔·오망성·긁힘·이끼6종. 작은 흔적3~6개 배치를 시도하고 안전한 공간이 부족하면 줄인다. 큰 의식문양은 일반 방에 드물게1개, 시설/보스/관문/튜토리얼은 혈흔·의식문양 제외다. 방/상승·하강 단계별 배치를 고정하며 문·시설·핵·장애물·전투 중앙을 피한다. 최대3방 투명 캐시·2px 표면을 사용하고 완화 모드도 정적으로 그린다.

**근접병·궁수:** 승인된 몸체·4프레임 보행과 베기 원화를 유지했다. 준비/발사/복귀 연결과 방향·보행 bob을 정리한 작업이며, 새 팔/활시위 원화 프레임을 만든 것은 아니다.

**궁극기·요정:** 화살비 첫/세 번째/마지막 접점 강조와 낮은 먼지, 석궁 반복 발사광 제한, 요정별 불씨/결정/번개 탄환과 짧은 발사 반응, 요정왕 빔 중심/외곽 농도를 나눴다. 탄환 수·피해/사거리·치명 판정은 바꾸지 않았다. 같은 틱에 소멸한 요정 탄환은 부가 발사 반응을 생략할 수 있다.

시안·원본·제작 프롬프트는 각 디자인 폴더에 보존했다. 실제 화면에서 시안과 동등한 미술 품질인지, 바닥 장식과 독/기관 예고·경험치가 충분히 구분되는지는 QA 전이다. 상세: [비주얼 개선](visual-refresh.md), [바닥 무늬 시안](design-drafts/floor-decals-20261121/README.md).

## 5. 검증 현황과 남은 작업

| 구분 | 확보한 근거 | 남은 확인 |
|---|---|---|
| 치명타·성장·신규 적 | 단계별 JS 회귀, 지원 적 단계 최종853/853 | 이후 변경을 포함한 전체 회귀/API 통합 |
| Pursuer·지원 적 외형 | 로컬 headless Edge 고정 장면·포즈·완화/844×390 QA | 정상 원정 플레이·실제 모바일·부하/난이도 |
| 기관 | 회귀9개 작성, 정적 연결 확인 | 작성 테스트 실행·실제 사격/해제/피격·전멸/하강·저장 |
| 맵·무늬·기존 몹·궁극기 연출 | 정적 호출/캐시·Canvas·변경 형식 확인 | 실제 PC/모바일 화면·자산 실패·가독성·성능 |
| 밸런스 | 구현 수치·보상/상한·측정할 항목 정리 | 화살비/석궁·치명/비치명·상승/하강의 실전 비교 |
| 운영 | 기존0.57 마지막 배포 기록 | 신규 릴리스 버전 정리·푸시·배포·공개 확인 |

최종 검증은 다음 순서로 묶는다.

1. 누적 코드/자산·저장 호환·설명/버전 정합성을 검토하고 전체 JS/API 검증을 수행한다.
2. 구저장/신규 원정, 상승/하강, 신규 조우·기관, 보스/해제 보상을 확인한다.
3. 정상 성장과 비교용 고정 빌드를 구분해 화살비/석궁 기여·보스 처치 시간·치명 발동률·XP/물약 수지를 비교한다.
4. PC/모바일 뷰포트·일반/완화·다수 적/분열 반복/소환 최대 부하와 경고 가림을 확인한다. 에뮬레이션과 실제 기기는 구분해 기록한다.
5. 발견한 실패를 수정·재검증하고, 통과한 누적 변경을 일괄 푸시/배포한 뒤 공개 파일·서비스를 확인한다.

현재 지침에 따라 문서 작성만으로 테스트·서버·푸시·배포를 실행하지 않았다. 다음 명시 배포 지시 때 위 검증과 배포를 진행한다.
