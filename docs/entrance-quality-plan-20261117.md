# 탑 입장 인트로 품질 개선 검토 — 2026-11-17

사용자는 현재 인트로가 캐릭터를 줌/이동하는 느낌이고 실제 모션이 부족하다고 지적하며 개선 방향을 물었다. 아래는 src/ui/entrance-scene.js와entrance-state.js를 읽어 정리한 제안이다. 현행 영상을 새로 재생/검증하지 않았으며 변경안을 승인·구현한 상태가 아니다. 기존 누적 미배포 변경은 보존한다.

## 현재 구조에서 확인한 원인

- 길이3.6초, 외부1초→접근/입장1.4초→문닫힘/암전으로 분할된다.
- 주인공은 타이틀의3셀 이미지에서0/1/2/1을0.32초마다 선택한다. 인트로 전용 보행/체중이동/시선/손동작 자산이 없다.
- 접근 장면은 y좌표를H*.97에서H*.74로 이동시키며 키높이를H*.31에서H*.19로 줄인다. 발의 실제 보행 순환과 바닥 접지가 아니라 이미지 이동·축소가 동작의 대부분이다.
- 문잎은 좌우 수평 slide로 닫힌다. 경첩을 축으로 한 회전·문짝 두께/그림자 변화가 없어서 무게가 약하다.
- 불꽃/안개/문빛/먼지는 이미 일부 있다. 이 효과를 더 늘리는 것만으로 캐릭터의 실제 동작 부족을 해결하기 어렵다.

## 추천: 전용 프레임을 쓰는 짧은 3컷 도트 컷신

목표5~6초를 검토한다. 길이 자체보다 실제 동작이 우선이다. 캐릭터·의상·활과 기존 탑의 디자인 결은 유지한다. 고정/짧은 컷 전환을 기본으로, 작은 카메라 이동은 보조만 쓴다. 긴 사전렌더 영상은 우선하지 않는다. 게임 속 픽셀 캐릭터와 어울리는 모션/분리 레이어를 쓰는 쪽이 크롭·효과완화·로드실패/스킵 대응에 유리하다.

|컷|제안 행동|화면에서 읽혀야 하는 변화|
|---|---|---|
|1. 탑으로 접근, 약1.5~2초|뒤쪽3/4 전신에서2~3걸음|발이 닿는 순간 중심 이동, 반대쪽 다리/팔, 망토·머리카락의 지연 움직임. 큰 줌 없이 인물과 입구 관계를 보여준다.|
|2. 문턱 앞, 약1.5~2초|잠깐 멈춤→고개/어깨로 입구 확인→활/손 정리→문 통과|사람이 의도를 갖고 들어가는 동작. 현재 이야기와 맞춰 이미 열린 문을 지나가되, 문을 밀도록 바꾸는 선택은 보드에서 명확히 제안한다.|
|3. 안쪽에서 돌아본 문, 약1.5~2초|인물이 어둠에 들어감→문이 경첩축으로 닫힘|빛이 몸과 바닥에서 좁아지고 무거운 문이 멎으며 먼지가 잠깐 떨어짐. 마지막 실루엣·정적 뒤 플레이로 연결.|

도트 그림의 세밀함을 늘리기보다 실루엣/발 접지/타이밍을 먼저 완성한다. 주인공을 크게 확대해도 새 포즈가 없다면 같은 문제를 반복하므로, 전용 행동 프레임 없이 줌·파티클만 추가하는 작업은 추천하지 않는다.

## 제작 패키지와 우선순위

1. 기존 주인공 정체성을 고정한 인트로 전용 동작 설계: 보행6~8프레임, 멈춤/시선·손동작4~6키포즈, 문 통과4~6키포즈를 목표로 잡는다. 이는 제작 목표이며 생성된 정적보드가 완성 연속모션임을 보장하지 않는다. 실제 프레임은 발 좌표·활/옷 실루엣·체격이 이어지는지 따로 확인해야 한다.
2. 배경은 전경/중경/문·광원/인물/그림자로 분리한다. 장면에 그려진 주인공을 통째로 옮기지 않는다. 문은 별도 잎과 경첩 앵커, 바닥 빛은 별도 효과로 만든다.
3. 세 컷의 통합 동작보드와 필요한 원화/포즈/별도효과를 한 패키지로 준비하고 한 번 디자인 확인을 받는다. 보드/프레임 후보와 움직임 시안의 역할을 구분한다. 지금은 미생성이다.
4. 승인 후 가장 중요한 걷기→멈춤→통과를 먼저 구현하고, 문 회전·그림자·가벼운 망토 후행 움직임을 연결한다. 효과음은 발 접지/문 움직임/닫힘의 실제 시각 시계에 맞추며 새 BGM은 범위에 넣지 않는다.
5. 마지막에 컷 길이와 최소 카메라 움직임을 조정한다. 기존 스킵, 비활성 탭/로드실패 처리, 게임 시간·저장/랭킹 정지를 유지한다. 반복 플레이에서는 스킵 접근성이 중요하다. 새 자동스킵 정책을 임의로 넣지는 않는다.

## 선택지와 검증 경계

- 추천안: 일관된 실제 보행 프레임+분리 레이어. 현재 게임의 결을 지키면서 움직임을 개선한다.
- 간이 리깅만 적용: 빠르지만 관절/망토를 과하게 휘면 종이인형 느낌이 남는다. 전용키프레임의 보조로 제한한다.
- 완성 영상 교체: 별도의 영상 제작/일관성 검수·압축·가로모바일 크롭·자동재생/음향/폴백 설계가 필요하다. 기존 이미지 줌 문제를 바로 해결하는 저비용 기본안으로 간주하지 않는다.

현재는 검토안 기록만 했다. 런타임·인트로 길이·원화/배포 자산·음향을 바꾸지 않았고 테스트·서버·브라우저QA·푸시·배포도 하지 않았다. 시안 전 승인 규칙과 사용자 일괄 배포 선호를 유지한다. 실제 iPhone/Safari·저사양 프레임/사운드·모바일 크롭·스킵/중단복귀 검증은 새 명시 배포 이후에 수행할 항목이다.
