# 7번 넷째 단위 — 브라우저 기록과 운영 신뢰성

## 실제 데이터 경계
- 진행 도전과 직전 백업, 종료 표식, 최근 30회 개인 기록, 온라인 등록 대기는 현재 브라우저의 HTTPS 사이트 데이터에 저장한다. 브라우저/기기를 바꾸거나 사이트 데이터를 지우면 이 로컬 자료는 자동 동기화되지 않는다.
- 온라인 순위는 서버 SQLite에 저장된다. 이름 등록은 탈출 후 사용자 동작으로 수행하며 공개 목록에는 닉네임·점수·시간·주력 기술이 표시된다. 개인 최고 기록의 연결은 브라우저 쿠키에 의존한다. 로컬 JSON 백업에는 쿠키가 없으므로 다른 기기로 옮겨도 진행 도전의 온라인 등록 권한이나 기존 공개 기록의 개인 연결은 복구되지 않는다. 사이트 데이터를 지워도 서버의 공개 기록은 삭제되지 않는다.
- 입구의 **도전 기록 → 기록 백업·가져오기**에서 허용된 로컬 기록만 JSON으로 내려받고 가져올 수 있다. 저장 데이터가 손상되면 입구의 오류 문구에서 원본을 먼저 내려받을 수 있다. 가져오기는 기존 값을 덮어쓰지 않으며 겹치는 파일 원본을 별도 브라우저 백업 키에 보관한다. HTTP→HTTPS 이전 경로도 유지한다. 백업 파일은 사용자가 직접 보관해야 한다.
- 현재 게임 안에서 로컬 기록을 직접 삭제하는 버튼은 없다. 사용자는 브라우저 사이트 데이터 설정으로 삭제할 수 있다. 공개 랭킹 기록의 삭제/문의 절차는 아직 제품에 없으며 별도 정책·연락 경로가 필요하다.

## 검증 범위
- `node --test` 403개 통과. Edge 로컬 QA `tools/qa/data-recovery-qa.mjs`: 백업에 허용된 3개 키만 포함되고 쿠키/타 사이트 키가 제외됨, 새 브라우저 가져오기와 같은 도전 이어하기, 기존 도전 충돌 보존, 허용되지 않은 파일 거부, 손상된 저장의 원본 다운로드, 모바일 에뮬레이션 가로/세로 화면 오류 0.
- 기존 `tools/qa/upgrade-qa.mjs`의 HTTP→HTTPS 자동 이전에서 신규/기존 도전 모두 보존됨.
- 코드 `e944243`, 운영 `release-20261006-095311-d3940d`. 서버 Python24개·Nginx·인증서/health 통과. 공개 Edge의 격리된 브라우저에서 백업/새 기기 가져오기·기존 기록 보존·불량 파일 거부·손상 저장 원본·모바일 가로/세로 오류 0. 공개 HTTPS 정적 8개 일치·HTTP308·랭킹/보안 쿠키/기존 HTTP 이전 오류 0, 운영 도전·점수 제출 없음.

## 서버 운영 경계와 후속 정보
- `ranking-operations.md` 기준 운영 DB는 SQLite이며 `spirebound-backup.timer`가 서버 내부에 매일 검증된 스냅샷을 14개 보관한다. `spirebound-ops-check.timer`는 15분마다 API/백업/인증서 상태를 점검한다. 현재 실패는 systemd/journal에만 남고 외부 알림은 없다.
- 다른 저장소에 복제하고 실제 복원 시험을 하려면 백업 목적지(예: Oracle Object Storage 버킷 또는 별도 서버)와 해당 목적지에 대한 권한이 필요하다. 장애 알림을 연결하려면 수신 이메일 또는 기존 알림 서비스 웹훅이 필요하다. 값이 정해지기 전에는 외부 복제·알림이 완료됐다고 표시하지 않는다.
