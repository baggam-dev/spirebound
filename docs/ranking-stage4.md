# 랭킹 4단계 — RANK 화면과 온라인 등록

- 메인 화면에 RANK 메뉴를 추가했다. 시즌 상위 100명, 이름·점수·시간·주력 기술과 이 브라우저의 최고 기록/전체 순위를 표시한다. 종료·빈 목록·통신 실패 상태를 구분한다.
- 새 도전은 플레이 시간을 진행하기 전에 익명 세션과 서버 도전 정보를 발급받는다. 실패하면 다시 연결·로컬 시작·돌아가기를 선택한다. 로컬 시작은 플레이와 점수 저장을 유지하되 온라인 등록 대상이 아니다.
- 발급 정보는 기존 도전 저장에 함께 보관한다. 기존 저장이나 보스 테스트에 온라인 자격을 소급 부여하지 않는다. 동일 서버 도전 재시도는 같은 runId를 유지한다.
- 탈출 결과에 이름 남기기 버튼을 표시한다. 이름 입력은 2~12자 규칙을 따르며 서버 금칙어 거부를 안내한다. 등록 공개 항목을 설명하고 나중에 등록할 수 있도록 한다.
- 결과 확정 시 제출에 필요한 집계 스냅샷을 별도 로컬 저장에 보관한다. 등록 버튼을 누르기 전에는 서버에 완료 기록이나 이름을 전송하지 않는다. 최근 30개의 대기/등록 결과를 RANK에서 다시 볼 수 있다.
- 제출 전 이름을 저장하고 네트워크 실패 후 재시도를 지원한다. 서버 응답을 잃었어도 동일 runId를 재전송해 원래 기록을 받는다. 더블 클릭을 억제하고 제출 완료/보류 상태를 구분한다.
- 세션이 없어지면 다른 참가자로 자동 재등록하지 않고 원래 쿠키가 필요함을 안내한다. 브라우저 저장 실패는 안내하며 현재 창에서는 메모리로 재시도할 수 있다.
- 조회·등록 중 화면을 떠난 뒤 늦게 도착한 응답이 현재 화면을 덮어쓰지 않게 한다. 닉네임과 서버 문자열은 HTML 이스케이프 처리한다.
- 코드: ranking-client.js(통신·대기 저장), ranking-ui.js(화면), game.js(새 도전/결과 연결), ranking.js(온라인 메타데이터 저장 검증), pixel-theme.css(반응형 순위·입력).
- 로컬 검증: 전체 Node 테스트 345개 통과(API 내부 Python 테스트 14개 포함). 클라이언트 7개 테스트는 시작 순서·저장 재개·제외 대상·실패 후 재시도·중복 요청·저장 실패·닉네임·타임아웃을 검사한다.
- Edge PC 1280×800 / 모바일 에뮬레이션 844×390, 390×844에서 실제 임시 SQLite API로 새 도전→탈출→금칙어 거부→응답 유실→새로고침→재시도→내 순위 흐름을 확인했다. 운영 랭킹에 테스트 기록은 넣지 않는다.
- 추가 검증: 로컬 시작 선택, 조회 실패 복귀, 모바일 100개 순위 스크롤, 닉네임 HTML 삽입 방지. 당시 HTTPS 전환·운영 점검은 5단계로 이관했으며 2026-09-29 완료했다(WORK_STATUS.md 참조). 실제 iPhone Safari 검증은 선택 과제로 남아 있다.
