## 현재 코드 기준

`game.js relicPanel`은 수호자의 유물함, 누적 적용 안내/보유 요약, 최대3개 카드, `relicPreviewMarkup` 및 지나가기 버튼으로 구성된다. 카드 클릭 시 바로 `claimRelic→save→resume`, 별도 장착/확인 단계가 없다. 현재 획득 후 전용 유물 배너는 없다.

`offerRelics`는 미소유 중 최대3개를 결정적으로 정하며 요정3종은 제안에서 제외한다. `grade:'unique'`인 실제 유니크만 보라 등급 표시 대상으로 삼는다. 별도의 보통/희귀/전설 등급 체계를 도입하지 않는다. 지나가기는 `relicClaimed=true`로 이 유물함을 소모하는 선택이므로 닫기/나중에 선택으로 표현하지 않는다. 교환 화면의 취소와는 다르다.

`relic-preview.js`는 플레이어 복제본에 유물을 적용해 실제 전후값과 요구 조건을 계산한다. 현재 획득 반경은 비교 행에 없지만 `collectXp/collectEssences` 모두30+pickup으로 계산하므로 수집 자석 비교30→100 행을 추가할 수 있다. 표시값은 실제 상태에서 계산하며 mockup의 예시 숫자를 하드코딩하지 않는다. 조건부 효과와 손실/획득 교환 설명은 보존한다.

## 패키지 방향

- 승인 스킬창 두루마리 계열을 따른다. 어두운 자주색 판/낡은 황동 테두리/크림색 카드/짙은 글자로 큰 제목→핵심 효과→실제 비교/조건을 읽게 한다. 장식은 본문보다 약하게 둔다.
- 보유 유물은 개수와 작은 실제 아이콘으로 요약하며 긴 전체 이름 목록은 접을 수 있는 상세로 보낸다. 많은 보유 유물/긴 이름에도 카드 높이가 밀리지 않게 한다. 현재 0~3 제안 수에 맞추고 후보를 임의로 채우지 않는다.
- 카드 전체를 한 번 누르면 즉시 획득하는 기존 동작을 유지한다. 금 테두리는 키보드 focus/hover 예시이며 자동 추천이나 선택 확정 상태가 아니다. 번호1/2/3은 순서 표식이며 새로운 단축키 지원 약속이 아니다.
- 예시: 수집 자석(경험치·정수 획득반경+70, 비교30→100), 순례자의 장화(이동속도+8%), 공허의 종(유니크,12초마다 적 끌어모음/보스 제외). 모두 실제 목록에 있다. 장화는 임의 전후 속도 숫자를 넣지 않았다. 조건이 필요한 다른 유물은 기존 requirement 문구를 우선한다.
- 지나가기는 보조 버튼으로 ‘이번 유물함 보상을 받지 않고 진행합니다’ 설명과 함께 유지한다. 새 확인 모달·재추첨·가격·장착 슬롯·유물 추가/교체는 제안하지 않는다.
- 가로 모바일도 3열을 유지하되 아이콘과 제목을 줄이고 짧은 핵심 효과를 먼저 표시한다. 긴 상세는 모달 내부 스크롤/펼침으로 처리하며 footer의 지나가기는 항상 접근할 수 있게 한다. 세로 모바일 UI는 이번 범위가 아니다. 실제 기기/치수 검증된 화면은 아니다.
- 실제 성공 획득 때 작은 유물 아이콘/이름/효과 2줄 배너와 한 번의 테두리 광을 표시한다. 추가 확인·전투 정지·보상 지연 없이 짧게 사라지며 위험 장판/조작/HUD를 가리지 않는 위치를 잡는다. 실패/지나가기에는 성공 배너를 띄우지 않는다. 방 이동·원정 종료·로드 때 재생하지 않는다. 효과 줄이기는 광 없이 정적인 텍스트로 표시한다. 기존 짧은 보상음을 재사용하는 방향이다.
- 새 유물 아이콘 전체 제작은 이번 범위로 확정하지 않았다. 그림 속 자석/장화/종과 보유2개는 배치 설명용이며 현재 아이콘 재사용을 전제로 한다. 승인 후 동일 외형의 새 raster 아이콘이 필요하다는 의견이면 범위를 따로 정한다. 기존 SVG/glyph를 Python/SVG 이미지편집으로 대체하거나 승인 asset을 재생성하지 않았다.
