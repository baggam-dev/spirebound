# 최우선 개편 — 넓은 던전 화면과 빌드 통합 창

2026-11-22 사용자가 시전 모션보다 UI 개편을 우선 지정했다. 참고 사진의 핵심은 넓은 전투 영역, 가장자리의 간결한 정보, 큰 조작 버튼이다. 스킬/유물/정수는 별도 창에서 관리하고, 뒤이어 사용자가 제안한 방 크기 변주까지 연결한다. 현재는 설계이며 시각 시안 승인·런타임 구현·테스트·배포 완료가 아니다.

## 순서

1. **시안 준비:** 같은 실제 게임 장면을 바탕으로 모바일 가로 전투 HUD와 빌드 창의 스킬/유물/정수 3탭을 한 패키지로 제시한다. PC 대응도 함께 설계한다. 외형 확인 전 런타임/CSS/배포 자산을 바꾸지 않는다.
2. **빌드 통합 창:** 기존 가방을 ‘빌드’ 진입점으로 정리. 스킬/유물/정수 탭, 아이콘 목록/선택 상세/현재 효과·수량. 열면 전투를 멈추고 닫을 때 기존 플레이 상태로 복귀한다. I 키·Escape·터치 닫기·키보드 탭 이동/초점 복귀, 좁은 화면 스크롤까지 묶어서 구현한다.
3. **전투 HUD·뷰포트 확장:** 화면 내 상시 스킬/유물/정수 나열을 통합 창으로 옮기고, 체력·XP/레벨·필수 전투 상태만 유지한다. 전투 캔버스를 가용 화면으로 확장하고 HUD는 위에 얹는다. 조작/안전영역/미니맵·위험 예고 가림을 조정한다.
4. **방 크기 변주 설계/시안:** 화면 확장 뒤 실제 월드의 작은 방/가로 회랑/세로 회랑/넓은 홀을 제안한다. 방별 크기/카메라·문/전투 밀도를 함께 검토한 다음 승인 범위부터 구현한다. 임의로 기존 모든 방의 크기를 당장 바꾸지 않는다.
5. 명시 배포 지시 때 누적 저장/일시정지·탭/화면비·입력 좌표·공격 예고/모바일·구저장 검증 후 푸시·일괄 배포한다. 평상시에는 수정/기록/로컬 커밋까지.

## 전투 화면 제안

- 상단 왼쪽: 체력·방어/중요 버프·XP/레벨. 회복/보호막 상태는 현재 의미를 보존한다.
- 상단 오른쪽: 기존 지도와 빌드·일시정지 진입. 탐험 지도와 방 크기를 확대하는 과정에서 길찾기 정보를 없애지 않는다.
- 하단 왼쪽: 누른 위치에 생기는 현행 자유 조이스틱. 검은 여백 고정으로 되돌리지 않는다.
- 하단 오른쪽: 큰 회피와 액티브/궁극기·물약. 게임 위 일부 겹침 허용, 손가락 접촉 영역/노치·홈바 안전영역 확보.
- 중앙: 전투/예고를 우선한다. 현재 목표·획득 알림은 짧게 표시하고 긴 설명/빌드 상시 나열은 창으로 이동한다.
- 전체 화면 활용은 우선 브라우저의 가용 뷰포트 기준이다. 모바일 브라우저 자체 주소창을 항상 숨긴다는 약속이나 자동 OS 전체화면 전환을 전제하지 않는다.

## 빌드 창의 실제 데이터

|탭|내용|범위|
|---|---|---|
|스킬|평타 계열/일반 스킬 레벨·진화, 액티브·궁극기, 현재 효과와 해금 안내|기존 성장/룰렛·진화 선택 흐름 유지. 창을 열었다고 재추첨·재분배하지 않음|
|유물|보유 유물 아이콘·중첩/희귀도·설명/현재 시너지|기존 relic-ui 상세·아이콘 활용. 장착/해제 기능을 임의로 추가하지 않음|
|정수|종류별 누적 획득 수와 그에 따른 효과|현 정수는 획득 즉시 적용된다. ‘소비할 재화 잔고/사용 버튼’으로 오해하게 만들지 않음|

`essences.js collectEssences`는 공격/이속/체력/공속/궁극기 정수를 즉시 적용하고 `player.essenceCounts`를 누적한다. 이전 대화의 ‘정수 사용처’ 제안은 현행 게임과 맞지 않으므로 이번에는 획득/적용 내역으로 명확히 정정한다. 최종 능력치는 유물/스킬 등 다른 출처도 포함되므로 정수 개수만으로 전체 효과를 역산해 표시하지 않는다.

기존 `index.html`은 header/topline/footer와 arena 안 collectionHUD/relicStrip/essenceStrip/skillStrip/statReadout 등으로 정보가 나뉘어 있고 `game.js bag()`에서 일시정지/저장을 수행한다. 새 창은 기존 상세 정보와 중단 보호를 모으는 작업이다. 기존 가방·유물창이 없었다고 전제해 중복 구현하지 않는다.

## 방 크기 변주의 경계

화면을 넓히는 것과 방의 충돌 영역을 늘리는 것은 다르다. 렌더/입력 좌표 변환부터 맞춘 뒤, 방 크기는 별도 월드 속성으로 다뤄야 한다. 고정 960×540 논리 화면·문 좌표/장애물 배치 등에 의존하는 코드를 확인해야 하며 CSS 확대만으로 구현했다고 하지 않는다.

- 긴 회랑은 진입 때 반대편 공격까지 미리 보이거나 안전하게 접근할 수 있어야 한다. 큰 방은 카메라/예고 가독성과 적 접근 시간이 달라진다. 작은 방은 회피·탄막 간격을 보장한다.
- 모든 방을 화면비대로 늘리면 휴대폰마다 전투 거리/난이도가 달라진다. 방의 월드 규격과 카메라 표시 영역은 구분한다. 넓은 폰에서 캐릭터만 늘어지지 않도록 비율 유지.
- 방 크기 추첨은 저장/재입장에도 유지하며 문 연결·진입 안전거리·상자/제단 접근·장애물 경로·적 생성·보스 전용 패턴·지도 표시에 일관되게 반영해야 한다.
- 첫 구현 후보는 일반 전투실/회랑/홀이다. 튜토리얼·시설·계단·보스 전용방은 기존 안전 배치를 우선 유지한다. 기존 원정의 방을 일괄 재추첨하는 동작은 이번 우선순위 지정만으로 허용됐다고 해석하지 않는다.
