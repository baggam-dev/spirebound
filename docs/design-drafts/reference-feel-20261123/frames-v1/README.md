# 대표 프레임 패키지 v1 — 검토용

최초 제작 기준 로컬 커밋 `0beed80`. 패키지 제시 후 사용자의 `다음진행`으로 주인공·모르도·FX 선택 프레임의 로컬 게임 연결을 진행했다. 문은 제품에 넣지 않았다. [index.html](index.html)은 사격/처치 조합·GIF·논리1×/2× 비교용 독립 시안이며 실제 게임·모바일 검증 결과가 아니다. 새 연결은 미검증·미배포 상태다.

후속 [보행·이동사격 패키지](../frames-walk-v1/index.html)에서 전신 보행8+이동 당김/발사8을 선택적으로 연결했다. 아래 이동 프레임 미포함 설명은 최초 패키지 범위이며, 최신 구현/제약은 후속 README를 따른다.

## 선택 프레임 로컬 연결

- `runtime-pack-manifest.json`의3아틀라스는 native PNG를 좌표 그대로 묶은 것이다. 주인공 정지 중 대기/당김/발사/회수/피격, 모르도 해골형 근접 베기·평시 피격·해골형 처치, 기본/정밀 화살 명중·모르도 격파 파열·실제 XP 획득 잔광에 연결했다. 주인공 착지 프레임은 기존 연속 구르기 원화를 대체하지 않았다.
- 이동 보행/이동 사격·액티브 시전·모르도 주문/기타 페이즈/다른 보스의 색·효과 줄이기는 원 표현을 보존한다. 이 패키지는 이동 상체 분리/보행 중간 프레임이 없어 새 전신 정지 자세를 이동 중에 섞지 않는다.
- 실제 선행 경로 `feedback-sprites.js`의 모르도 몸체92.4px/발21에 맞췄다. `mordo-phase1-sprite.js`의84px/발29는 하위 fallback이므로 이를 주 경로 크기로 오인하지 않는다. 새 근접 자세는 공통 몸체보다 먼저 선택한다.
- 새 이미지 요청은 `presentation-assets.js`의 선택적 요청에만 연결한다. 필수 로딩용 `*Ready` Promise를 추가하지 않아 지연/실패/크기 불일치 시 기존 그림과 절차형 FX로 돌아간다. 배우·AI·피해·보상/저장 필드를 쓰지 않는다.
- `runtime-pack-image-report.json`은3아틀라스의 실제 투명도/48색 한도 정적 확인만 통과한 기록이다. 실제 게임 렌더링·실기기·성능 검증/테스트·푸시·배포는 수행하지 않았다.

## 정규화와 정적 확인

- `build-review.py`는 원본을 보존한 채 균등 셀을 분리하고, alpha>192의 핵심 픽셀을 기준으로 프리뷰를 만든다. 기준 자세의 배율을 다른 자세에도 그대로 적용하며, 웅크리거나 붕괴하는 자세를 억지로 키우지 않는다. 기준점은 `frame-map.json`에 기록한 초안이며 제품용 정밀 앵커 확정값이 아니다.
- 작은 크기 프리뷰는 nearest 축소, 가족별 공통47색 팔레트+정규화한 투명색1개, binary alpha를 사용한다. 원본의 희미한 가장자리/광휘는 프리뷰에서 빠진다. 이 방식만으로 수작업 도트 클러스터·모션 품질이 완성됐다고 판정하지 않는다.
- `source-image-report.json`: 선택4장의 크기/투명 채널 확인 통과. `native-image-report.json`:28프레임의 실제 투명도/48색 한도 확인 통과. `frame-map.json`:alpha>192 핵심 픽셀의 셀 경계 접촉0건. 투명 배경의 어두운/밝은 합성 비교용 접촉시트를 육안 확인했다. 기본 보고서 통과는 **제품 적용 승인/전체 기술 검증 통과가 아니다**.
- `native-contact.png`는 논리 크기1×, 가족별`*-review.png`는2×, GIF는3× 핵심 자세 검토용이다. GIF의 시간은 자세를 읽기 위한 임시값이며 실제 공속/시전/회피 시간을 바꾸는 설계가 아니다. 중간 보간·보행 주기·전 방향 모션을 만든 것이 아니다.
- 위 작업은 이미지 파일의 정적 분석과 검토 자료 생성이다. 게임 소스 실행·구문 검사·단위/통합/게임 브라우저 QA·실기기·성능·음향·푸시·배포는 수행하지 않았다. 앞선1~3차 회귀23개도 미실행 상태다.

## 확인된 제약과 다음 순서

1. 주인공의 기존 정체성은 유지하지만 자세별 손/활·천의 디테일과 일부 체적 차이는 정밀 정리해야 한다.58px에서 보이는 윤곽이 기준이며, 큰 원본의 장식만 보고 승인하지 않는다.
2. 모르도는 **해골형 대표 자세만** 있다. 균열형/최종 악마형·단계 전환·전 방향·이동 중간 프레임은 후속 제작 범위다. 이6장으로 전체 보스 패키지가 완성된 것은 아니다.
3. 문은 큰 봉인문 정면형이다. 현재 일반문의80×35 및 좌우 벽용 규격과 세로 비율이 달라 그대로 끼우거나 잡아늘릴 수 없다. 큰 문 배치 여백·위/아래/좌/우 변형과 이동/클리핑 규칙을 함께 설계한 후 반영한다. 봉인/해제의 차이는 작은 색 표식에 치우쳐 있어 별도 봉인 형상/해제 움직임을 후속 보강한다.
4. FX는 실제 전리품 객체가 아니라 잔광/파편이다. 향후 보상 연출은 기존 실제 XP/아이템 상태를 읽어야 하며 새 지급/랜덤 드롭을 만들지 않는다. source의 부드러운 외곽은 정리했으나 픽셀 단위 프레임 연결은 더 다듬어야 한다.
5. 대표 외형+모션+별도 FX를 **이 페이지 한 패키지로** 검토한다. 제품 반영 전 패키지 확인 규칙을 유지하고 부위/자세마다 확인을 반복하지 않는다. 확정 후 중간 프레임·페이즈·방향 변형을 묶음 제작·정규화하고 런타임에 연결한다. 새 명시 배포 때 누적 검증한다.

출처/호출/선택 상태는 `asset-manifest.json`, 전체 생성 요청은 `prompts.md`, 셀/배율/기준점은 `frame-map.json`에 있다. 참고 타 게임의 영상 프레임·소리·UI는 제품 이미지로 사용하지 않았다.
