# 주인공 보행·이동 사격 v1

기준 `01cc358`, 기존 승인 주인공과 대표 방향 안의 모션 확장. 새 보행8자세+이동 사격8자세(당김4/발사4)를 로컬 게임에 연결했다. [검토 페이지](index.html), [1× 비교](native-contact.png), [확대 비교](pose-review.png)를 함께 본다. 테스트·푸시·배포 완료 자료가 아니다.

## 제작/표시 기준

- built-in imagegen2회, 요청 전문은`prompts.md`. 같은 머리/스카프/갑옷/활을 유지한1536×1024 두 원본은 그대로 보존했다. 실제 alpha0 영역을 확인했다. 원본 셀은384×512, 각8자세다.
- `build-review.py`는 공통58px 몸체 배율과 발 기준으로16프레임을 정리한다. 상체·하체를 임의 절단해 붙이지 않고 전신 프레임을 사용한다. 원본은 수정하지 않는다. native128×104, 발 기준(64,90), game local feet+22를 기존 정지 프레임과 맞췄다.
- 알파>192 핵심 픽셀→nearest축소→기존 정지 주인공 팔레트 재사용→48색 이내(투명색 포함)로 정규화했다. 공통 배율·각 초안 루트는`asset-manifest.json`에 기록한다. 자세별로 확대해서 머리 크기를 맞추는 방식은 쓰지 않는다.
- 이미지 정적 검사: native16장과512×416 제품 아틀라스1장의 실제 투명도/48색 한도 통과(`image-report.json`). 원본 핵심 픽셀 셀 경계 접촉0, 최소 여백1px인 활 끝이 있으므로 최종 프레임 여백은 별도 검토 대상이다.1×/확대/밝은 배경 접촉시트를 육안 확인했다.

## 연결 방식

- `referenceHeroMoveFrame`은 이미 관찰된 이동 거리 기반`p.walk`를 읽고8단계 위상을 선택한다. 실제 이동량·속도·공속·사격/RNG·배우/저장 필드를 쓰지 않는다. 정지 사격은 기존 선택 프레임을 유지한다.
- native 다리 영역(32,73)~(100,93)의 알파 실루엣을 정적으로 비교하니, 양쪽 사격 행 모두 보행0~7에 대해`0,1,2,3,0,1,2,3` 순서로 가장 가까웠다(`phase-correspondence.json`). 따라서`step % 4`로 같은 위상을 선택하고, 당김/발사 때 걸음을0으로 리셋하지 않는다. 이 수치는 모션 검증이나 발 미끄러짐0을 보장하지 않는다.
- 실제 recoil>0은 발사 행, 실제 준비 상태는 당김 행, 나머지는 보행 행을 쓴다. 효과 줄이기는 건너뛴4개 보행 위상과2개 사격 위상으로 줄인다. 기존 액티브 시전·구르기·사망 우선 경로는 바꾸지 않았다.
- `reference-hero-move-frames-v1.png`는 선택적 요청에만 추가한다. 크기 검증/실패 fallback을 유지하고 필수`*Ready` 대기에 포함하지 않는다. 새 이미지가 실패하면 기존 보행·이동 사격으로 돌아간다.

## 검증과 제약

추가 회귀3개를 작성만 했다. 기존 선택 요청/아틀라스 개수 fixture를4가족에 맞췄다. 누적1차 이후31개 회귀는 미실행이며, 게임 소스/구문 실행·게임 브라우저 QA·실기기/성능·음향·푸시·배포는 수행하지 않았다. 정적 이미지 확인과 diff 검토만 했고 운영0.63은 그대로다.

단일 시점의 미러링이며 전 방향 전용 원화, 착지 연결 중간 프레임, 조준 방향이 이동 방향과 반대일 때의 정밀 동작은 별도 검토가 필요하다. 자세별 미세 체적/루트 차이와4단계 사격의 계단감은 실제 게임/배포 전 검증에서 확인해야 한다. GIF는 고정90ms의 검토용 재생이며 실제 공속·이속을 뜻하지 않는다. 다음은 일반문80×35·벽 방향별 규격 패키지다.
