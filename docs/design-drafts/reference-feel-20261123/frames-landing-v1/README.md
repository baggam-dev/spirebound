# 주인공 착지·기립 6프레임

기존 승인 주인공의 모션 확장 검토용 가족이다. 제품 `src/`·`assets/`에는 넣지 않았다. `index.html`에서 재생/기존 대기 복귀/1x·2x·밝은 배경 비교를 한 번에 볼 수 있다.

## 제작과 기준

- built-in imagegen 한 번, 기존 hero-poses-source를 정체성 참조. 전체 프롬프트와 원본 위치는 prompts.md. 복사한 원본을 보존했고 manifest.json에 SHA256을 기록한다. 다른 게임 영상·이미지·소리를 사용하지 않았다.
- 원본1536×1024 RGBA, 512×512 셀6개, alpha0~254. A>192 핵심 경계는 어느 셀에도 닿지 않았다. 최소 여백38px이다.
- 마지막 기립 자세의 핵심 높이427px를58px로 만드는 공통배율58/427 사용. 낮은 자세만 따로 확대하지 않았다. 모든 native는128×104, 발기준64,90. 수평 몸기준은 수동 추정이며 manifest에 원본 좌표를 보존한다.
- 기존 reference-hero-frames-v1의 실제 불투명 팔레트를 재사용하고 최근접 리사이즈·이진alpha·투명RGB0 적용. native6장의128×104/실제투명도/48색 상한을 asset_report로 정적 확인했다. 첫 보고 명령의 와일드카드가 확장되지 않아 파일없음으로 실패했으며 명시적인6경로로 다시 실행한 image-report.json이 최종 통과 결과다.
- 검토 atlas384×208은 이 폴더에만 있다. 재생 간격60ms 및 마지막500ms는 검토 편의를 위한 값이고 게임 설계 확정 시간이 아니다.

## 코드에서 확인한 연결 조건

현재 `companion-roll-art.js`는 구르기4장을 실제 roll.elapsed/duration으로 선택하고 roll이 없으면 즉시 일반 자세로 돌아간다. `roll.js`의 실제 회피는 기본0.28초/swift0.224초이며 별도 착지경직이 없다. 새 그림 때문에 실제 이동·무적·공격·행동 시간을 늘리면 안 된다.

후속 연결은 기존 구르기 후반에 회복 자세를 분배하거나, 실제 종료를 관측한 뒤 짧은 표시상 회복을 쓰되 즉시 이동·사격·시전·피격이 우선하도록 구성한다. 첫 관측/저장로드/방이동에서 착지를 재생하지 않고 slash 진화는 기존 질주 원화를 유지한다. 선택적 이미지 실패 시 기존 구르기→대기 경로로 돌아가야 한다. 별도 분진은 실제 종료 위치에만 붙이고 캐릭터 PNG에는 효과를 굽지 않는다.

이 조건은 연결 계획이며 아직 구현하지 않았다. 기존 옛 구르기와 새 몸체의 정체성/체적 차이, 손·활 자세, 마지막 새 기립→기존 idle 연결이 실제 게임에서 자연스러운지는 미검증이다. native6의 정적 검사와 접촉시트 육안 확인을 게임 모션 검증으로 해석하지 않는다. 게임 구문/테스트/브라우저·실기기/푸시·배포는 없고 운영0.63·누적33개 미실행 회귀는 그대로다.
