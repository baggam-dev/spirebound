## 우리 아트 기준

기존 주인공 정체성과 어두운 성채는 유지한다. 모든 것을 밝고 복잡하게 만들지 않고, **묵직한 실루엣 + 읽히는 도트 덩어리 + 폭발 순간의 고명도**를 기준으로 한다.

1. 캐릭터: 얼굴·손·무기 끝을 큰 명암 덩어리로 분리. 발 고정과 무게 이동을 먼저 맞추고 준비/발사/회수 자세 차이를 키운다. 고해상도 이미지를 작은 크기로 줄이는 것만으로 도트 완성도를 판정하지 않는다.
2. 보스: 잡몹과 다른 덩치·위압적인 자세·발동 직전 형태 변화. 크기는 몸체 표시와 실제 위험 판정을 함께 확인하고 임의로 판정 확대하지 않는다. 모르도 등 기존 보스마다 고유한 균열/붕괴 형태를 둔다.
3. 오브젝트: 벽·바닥은 캐릭터보다 낮은 대비, 문/봉인/보상은 별도 발광·명암. 작은 장식마다 동일한 번쩍임을 넣지 않는다. 등불·기둥은 문과 시야 통로에서 비킨다.
4. 도트 효과: 중심은 밝은 작은 코어, 중간은 속성색, 외곽은 어두운 파편. 매끈한 흐림만 쌓기보다 계단형 궤적/조각/짧은 잔상을 기본으로 한다. 화면 기준 픽셀 규칙과 정수 스케일/nearest를 일관되게 적용한다.
5. 색 역할: 기본 사격은 담금빛/뼈색, 화염은 주황, 서리는 청백, 봉인·타락은 보라. 적 예고는 외곽선/무늬로도 구별한다. 전체 색 범위는 대표 장면 시안에서 확정한다.

## 전투 리듬 패키지 — 제안 시작값

|사건|타격 반응|잔향/음향 역할|제약|
|---|---|---|---|
|일반 명중|대상 국소 밝기40~65ms, 방향성 작은 스파크4~6개|짧은 이탈음+금속/살점 명중음, 꼬리100~180ms|전역 정지·상시 화면 흔들림 없음|
|치명타/강한 액티브|대상 포즈 유지35~60ms 후보, 월드 흔들림2~4논리px/100~150ms, 스파크12~20개|낮은 충격음+짧은 고역층, 큰 숫자는1번|시각 포즈 유지와 실제 시뮬레이션 정지를 구분. 기본은 시각만, 진짜 시간 정지는 밸런스 별도 검토|
|구르기/빠른 이동|출발 파편, 뒤쪽2~3장 짧은 잔상,120~180ms 감쇠|짧은 바람/발 구름|현 이동 속도 변경 없이 먼저 비교. 실제 이동 버프는 후속 후기와 함께 판단|
|일반 적 처치|피격 방향으로 분해/무릎 꺾임→작은 조각→빠른 소멸|재질별 짧은 파열|통째 사라짐/흰 플래시 반복보다 형태 변화 우선|

다단히트는 매 탄마다 큰 반응을 재시작하지 않고, 같은 대상/짧은 구간을 합친다. FX 전용 난수와 고정 입자 상한을 사용한다. 실제 플레이 스피드는 스킬 후딜·이동·목표 전환도 좌우하므로 광고를 보고 게임 전체 배속을 올리는 방식으로 결정하지 않는다.

## 검토용 모션 시안과 진행 순서

`motion-draft.html`은 우리 기존 거인/모르도 이미지를 사용한 독립 Canvas 연출 시안이다. 일반 명중·강타·보스 격파의 효과 강도/타이밍을 버튼으로 비교한다. 신규 캐릭터 원화, 실제 전투 구현, 검증 완료 제품이 아니다. 오디오 시안은 포함하지 않는다.

1. **대표 한 장면 패키지**: 기존 주인공+일반 적+모르도+문/기둥/바닥, 준비/발동/피격/사망, 별도 FX, 보스 보상 마무리를 PC·모바일 실제 크기로 제시한다. 캐릭터별 파편 승인을 나눠 받지 않는다.
2. **공통 타격 레이어**: 기존 이벤트 훅·중복 억제·국소 플래시·숫자 합산·재질 음향·월드 전용 흔들림을 적용한다. 체감 속도부터 먼저 개선한다.
3. **보스 처치 파이프라인**: 실제 정산과 연출 분리, 모달/남은 적/페이즈·스킵·불러오기 경계 처리. 모르도1종에서 완성한 뒤 각 보스로 확장한다.
4. **자산 가족 확장**: 통일한 픽셀 크기/광원/명암/프레임 앵커로 나머지 캐릭터·오브젝트·스킬을 묶음 제작한다. 기존 승인 주인공을 임의로 재디자인하지 않는다.
5. **새 명시 배포 시 검증**: 재질/다단히트 합치기/보상1회/모달/일시정지/로드·방 이동/실패 fallback·모바일·성능·효과 줄이기, 필요한 회귀를 묶어 실행한다. 지금은 테스트·푸시·배포하지 않는다.

최초에는 디자인 사전 시안 규칙에 따라 분석·모션 시안만 작성했다. 이후 사용자 `ㄱㄱ`를 제시된 연출 방향의 진행 승인으로 반영하여 기존 외형의 공통 피드백부터 연결했다. 새 원화는 `art-board-v1.png`의 대표 패키지 확인 후 제품용 프레임으로 제작한다. 추가 플레이 후기와 기존 가로 화면 TODO는 유지한다.

## 1차 로컬 구현 및 대표 보드

- `combat-impact.js`: 실제 fresh damage만 받아 대상별 국소 밝기40/60ms, 방향 파편 fallback,16개 상한·치명 우선, 대상별180ms 중복 억제. 기존 화살·속성·액티브·치명 파편과 겹치면 fallback만 생략한다. DoT의 동일 snapshot 재타격은 반응을 다시 시작하지 않는다.
- `room-stage.js`: 전용 월드 offset을 추가해 기존 수호자 등장·모르도 붕괴·치명·보스 마무리 흔들림을 합성한다. HUD/입력/캡처의 논리 좌표는 그대로 두고 최종 월드 변환만 최대8px로 제한한다. 전역 시뮬레이션 hit-stop은 추가하지 않았다.
- `boss-clear.js`:1.8초의 국소 충격/파편/기존 몸체 사망/보상 강조를 연결한다. 새 실제 보스 XP가 남아 있을 때만 빛기둥을 그리며 XP 지급·위치·흡수는 기존 로직을 따른다. 그림자·중간 분열은 축하를 만들지 않으며 적/적탄이 남으면 큰 문구를 숨긴다.
- `art-board-v1.png`: 기존 주인공/모르도 참고로 built-in imagegen1회 생성한6패널 대표 방향 보드. 아트·타격·오브젝트·보스 자세·파열·보상을 함께 본다. 독립 PNG, 제품 아틀라스·프레임·새 전리품 목록이 아니다. 보드의 사선 원근·표시 비율은 실제 탑다운 방/충돌·96px 등 제품 크기에 맞춰 별도 제작해야 한다.

- 1차 당시 후속: 즉시 성장/유물 모달 가림, 숫자 합산·음향·구르기 잔상, 새 캐릭터/오브젝트 자산 가족과 프레임 정규화. 이 중 패널 표시·보스 음향·구르기 잔상은 아래2차에서 연결했다. 전체 개편 완료가 아니다.

## 2차 로컬 구현 — 패널 표시·보스 음향·구르기 잔상

- `boss-reward-reveal.js`는 이미 생성/저장된 성장·메인·진화·액티브·유물 패널의 DOM을 그대로 유지하면서 보스 시각 나이1.2초까지만 `inert`/`aria-hidden`과 CSS로 감춘다. 선택지 생성 RNG, 실제 지급, 기존 모달 일시정지 시점을 미루지 않는다. 가림 중에는 기존 사망 시각 FX만 이어서 감쇠하며 시뮬레이션은 진행하지 않는다. 첫 가림 프레임의 중복 감쇠를 피한다.
- 스킵/ESC는 보스 시각 상태만 끝내고 동일한 선택창을 보여준다. Tab은 가려진 선택지로 들어가지 않으며, 원래 초점·aria 속성을 복구한다. 다른 패널/lease 손실/방 변경/타이틀·로드 reset 시 임시 가림막을 정리한다. 모르도의 기존 귀환 붕괴/키 진행 흐름과 일반 일시정지·설정·오류창은 가리지 않는다.
- `takeBossClearCues`는 실제 완료 이벤트에서 만든 시각 상태에 한해 충격0초/파열.18초/해방.75초를1회 소비한다. 지나간 재생 창은 생략하고 스킵·로드에 과거 소리를 몰아 재생하지 않는다. 새 합성음은 기존world 버스8보이스·우선순위·해금·음소거를 따르며 충격만 combat 버스를 짧게 duck한다. 구르기 성공 시에만 `rollRush`를 재생한다. 실제 청취/장기 믹스·음압 측정은 미실행이다.
- `roll-trail.js`는 실제로 관찰한 위치와 구르기 자세를35ms 간격·최대3개/140ms로 그린다. 벽 뒤로 좌표를 외삽하지 않으며 시각 스냅샷에 게임 객체 참조를 보관하지 않는다. 효과 줄이기는 생략하고 방 이동·로드/reset 시 정리한다.
- 추가 회귀8개(패널4/잔상2/보스 큐1/음향1)를 작성했으나 실행하지 않았다.1차7개와 합쳐 누적15개 작성만 된 상태다. 정적 검토와 `git diff --check`만 수행, 구문/게임·브라우저/실기기·성능/청취·미터/푸시·배포는 별도 배포 지시까지 보류한다.
- 다음 남은 범위: 숫자 합산/가독성, 확정 보드에 맞춘 실제 캐릭터·오브젝트 가족의 원화와 모션 프레임 제작·정규화. 게임 전체 속도나 전투 판정·보상/저장 필드는 바꾸지 않았다.

## 3차 로컬 구현 — 실제 피해 숫자와 가독성

- 기존에는 일반 피해 숫자가 없고 치명/약점 등 문구가 있었으므로, 새 `damage-numbers.js`에 실제 피해 결과 기반 숫자를 만들었다. 같은 대상의160ms 고정 창 안에서 일반·치명 성분을 나눠 합산한다. `criticalDamage`를 실제 적용량 안으로 한정하고 나머지를 일반 피해로 표시한다. 반복 DoT도 실제 적용량이면 합산하며 snapshot ID가 같다는 이유로 피해를 누락시키지 않는다. 오버킬은 HP 차이로 다시 계산하지 않고 `damage`의 실제 적용량만 쓴다.
- 시각 상태는24개·수명650ms, 동시 표시8개(PC)/5개(터치)/4개(효과 줄이기)로 제한하고 치명을 우선한다. 창/수명을 마지막 타격마다 무한 연장하지 않는다. 일반은 작은 담색 숫자, 치명은 큰 금색 숫자+`!`, 큰 값은K/M을 쓴다. 부동소수 오차로 순수 치명타에 가짜 작은 일반 숫자가 생기지 않게 보정한다.
- `combat-readability.js`는 기존 정수 획득·약점·플레이어 피격/공격원 문구의 자리를 먼저 보호한다. 숫자만 가까운 빈 행을 찾고, 자리가 없으면 생략한다. 숫자 표시 예산은 실제 전투 합계/피해 기록을 제한하지 않는다. 선택된 치명 숫자 대상의 중복 일반 `치명!` 문구만 통합하며, 약점 치명 문구와 원 타격 FX·음향은 보존한다.
- 모든 합산은 별도 WeakMap 상태이며, 방/로드/reset에서 정리한다. 첫 렌더링에도 현재 방과 일치하는지 확인한다. 보스 보상창 가림 중에는 시각 수명만 이어서 감쇠한다. 실제 게임 수치/시간·판정/AI·RNG·정산·저장 필드는 변경하지 않는다.
- 추가 회귀8개(숫자6/배치2)를 작성만 했다.1~3차 누적23개 미실행이며 정적 검토·diff 확인만 수행했다. 실제 가독성·브라우저/실기기·성능은 새 배포 지시 때 검증한다.
- 다음은 대표 아트 보드를 실제 캐릭터·오브젝트·모션 프레임 패키지로 구체화하는 단계다. 새 원화의 제품 반영 전 패키지 검토 규칙은 유지한다.

## 마감 기준

### 대표 프레임 패키지 v1

`frames-v1/index.html`에 주인공6자세·모르도 해골형6자세·큰 봉인문4상태·별도 FX12프레임, 총28장을 묶었다. 사격/명중·보스 붕괴/문 개방을 조합하는 독립 시안과 GIF/논리1×·확대/명암 합성 자료, 전체 프롬프트·출처/선택 이력·좌표/초안 기준점·정규화 스크립트를 포함한다.

선택 원본4장의 크기/투명 채널 및 native28의 실제 투명도/48색 한도, alpha>192 핵심 픽셀의 셀 경계를 정적으로 확인했다. 최초 모르도의 배경막은 보정본으로 교체하고 원본을 제외 이력으로 보존했다. 독립 HTML 조합 화면과 접촉/명암 이미지를 육안 확인했다. 이 작업은 제품 게임 QA가 아니며1~3차23회귀는 여전히 미실행이다.

아직 전체 가족의 완성 자산은 아니다. 핵심 자세 사이의 중간 프레임/이동/전방향/모르도 다른 페이즈가 없어 현재 연결은 선택적이다. 정면 큰 봉인문은 일반문80×35와 비율이 달라 일반문 대체에 사용할 수 없다. [패키지 README](frames-v1/README.md)의 제약을 유지한다. 기존 배포0.63은 그대로다.

### 선택 프레임 로컬 게임 연결

새 `reference-frame-art.js`와3개 native 아틀라스는 선택적 요청에서만 활성화한다. 정확한 이미지 크기 확인 후 읽고, 로딩 지연/실패 시 원 표현을 유지한다. 새`*Ready` 필수 대기나 전투/저장 필드를 만들지 않는다. 실제 우선 몸체는`feedback-sprites`의 모르도92.4px/발21이며,84px/발29는 하위 fallback이다. 앞선 크기 추정은 이 정적 경로 확인으로 정정했다.

주인공 정지 중5자세(대기/당김/발사/회수/피격), 해골형 모르도 근접베기·평시피격(120ms,1초 간격)·해골형 처치를 연결했다. 이동용 프레임이 없어 이동 보행/이동 사격·시전/회피는 기존 원화를 쓴다. 새 모르도 근접 자세는 우선 공통 몸체보다 먼저 선택하며 주문/위험 예고·다른 페이즈·그림자는 대체하지 않는다. 기본/정밀 화살 명중과 모르도 격파 파열은 해당 프레임을 쓰고, XP 도착 잔광은 실제`xpPickup`에만 붙인다. 타 보스 파열·감소 효과/절차형 fallback은 그대로다.

3아틀라스의 실제 투명도/48색 정적 확인은 통과했다. 추가5회귀는 작성만 했고 누적28개 미실행이다. 실제 게임·구문·단위·브라우저/실기기·성능·음향 검증·푸시·배포는 수행하지 않았다. 다음은 이동 사격 상체/보행·착지 중간 프레임과 일반문 규격·방향 패키지다.

### 주인공 보행·이동 사격 확장

상하체를 임의 절단하면 이음새가 생겨, 같은 정체성의 전신 보행8·당김4·발사4 프레임으로 확장했다. 공통58px 배율/발 기준과 기존 정지 팔레트를 사용하고 제품 아틀라스512×416을 선택적 로더에 추가했다. 원본2장·prompt·출처/sha·변환 스크립트·루트/좌표·GIF/정적 비교는 `frames-walk-v1`에 있다.

실제 이동 거리의`p.walk` 위상을8단계로 읽고, 사격은 새 걸음으로 시작하지 않고 같은 위상의 행만 바꾼다. 다리 영역의 알파 정적 비교 결과 당김·발사 모두 보행0~7과`0,1,2,3,0,1,2,3` 순서로 대응하여`step % 4`를 사용했다. 실제 recoil/준비 상태만 읽고 게임 속도·사격 시간/피해·보상/저장·RNG를 바꾸지 않는다. 액티브 시전·구르기·정지 프레임·실패 fallback은 유지한다.

native16+제품1장의 투명도/48색 정적 검사와 접촉시트 육안 확인만 했다. 원본 핵심 픽셀의 셀 경계 접촉은 없지만 활 끝 최소 여백1px, 미세 루트/체적·역방향 조준·4단계 사격 연결은 실제 게임 검토 대상이다. 회귀3개를 추가 작성하여 누적31개 미실행이다. 게임 구문/테스트·브라우저/실기기·성능·음향·푸시·배포는 여전히 미실행이며 운영0.63을 유지한다. 다음은 일반문 규격/방향·봉인 상태 패키지다.

- 작은 화면에서 주인공/보스/문·적 위험이 먼저 읽힌다. FX가 켜진 상태에서도 다음 회피 방향을 알 수 있다.
- 일반 명중→치명타→보스 최종 처치의 강도 차이가 분명하다. 다단히트 중에도 화면이 계속 흔들리거나 백색으로 덮이지 않는다.
- 효과 줄이기는 플래시/흔들림을 낮추면서 파편 방향·문구·보상 단계를 남긴다.
- 대표 캐릭터의 포즈·프레임 앵커·원래 표시 크기를 확인한다. 타격 연출 때문에 실제 판정/저장/RNG/랭킹 시간이 달라지지 않는다.
- 참고작에서 추출한 이미지·소리·UI·고유 캐릭터·보스 디자인은 배포 자산으로 사용하지 않는다. 우리 신규 자산은 출처/도구/수정/승인 기록을 남긴다.
