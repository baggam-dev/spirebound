# 일반문 방향·상태 기하 시안

검토 전용. 제품 소스와 배포 자산은 수정하지 않았다. 기존 큰 정면 봉인문을 찌그러뜨려 쓰지 않고 일반문 규격에 맞는 형태를 먼저 비교한다. `index.html`과 `comparison.svg`에 4테마×4방향×3상태 48안을 묶었다. 새 대형 디자인 방향을 제품에 넣기 전 패키지로 보여주는 단계다.

## 실제 코드에서 확인한 기준

- `src/game/game.js`의 문 루프는 `doorFramePoint(r,d)` 위치에 검은 바탕을 그리고 `drawDoorFrame(...,d%2,locked,floor)`를 호출한다. 현재 API에는 방향 전체가 없어 북/남·동/서 개별 안쪽 방향을 구분할 수 없다.
- `src/rendering/pixel-world.js`는 층별 테마 함수를 먼저 호출한다. fallback만 바꾸면 기존 테마 원화에는 적용되지 않는다. 상하 기본80×35, 측면29×70이다.
- `environment-art.js`의 0층 원화 높이는40 예외다. `archive-art.js`는80×35/70×29를 쓰고 측면은 회전한다. 이 차이는 실제 벽·바닥 경계와 함께 검토해야 한다.
- `world/doors.js`는 연결 방의 문 위치와 진입 공간을 관리한다. 시안은 배치·장애물 carving·저장·문 통과 판정을 바꾸지 않는다.

## 패키지 방향

석조는 밝은 석재 테두리, 기록보관소는 보라 회색, 프리즘은 청록, 상층은 철·구리 계열로 재료만 구별한다. 봉인은 가로 빗장과 중앙 마름모 봉인, 해제는 빗장 분리와 중앙 틈, 개방은 빈 통로와 세 줄 문턱으로 모양을 구별한다. 빛/불꽃은 추후 별도 FX이며 원화에 지속 오라를 굽지 않는다.

해제 중 상태는 연출 제안이며 새 게임 상태가 아니다. 실제 잠금→개방 변화만 읽어 짧게 재생하고 최초 입장·로드에서는 이미 열린 문을 재폭발시키지 않는 구성이 필요하다. 미구현 제안 시간: 0.25초 빗장 분리, 0.15초 문턱 잔광. 효과 줄이기에서는 즉시 최종 모양으로 바꾼다.

## 승인 방향 내 다음 연결 계획

1. 문 좌표·충돌은 유지하고 `d` 전체를 시각 계층에 전달, 안쪽 문턱 방향을 북/동/남/서에 맞춘다. 기존 호출과 fallback을 유지한다.
2. 모든 층별 원화의 공통 프레임/문턱 계층을 정리한다. 잠금 빗장은 기존 locked 값을 읽고, 개방은 막힌 판처럼 보이지 않게 한다. 특수 봉인문·입구·최종 탈출문은 별도다.
3. 횃불/장식 배제영역은 실제 문 프레임을 기준으로 외측8px·안쪽18px 후보를 사용한다. 기존 중첩 방지 코드부터 확인하고, 장식만 생략하며 조명·장애물·진입 공간을 무조건 삭제하지 않는다. 위치가 바뀐 문에도 동일 적용한다.
4. 큰 방향이 확인되면 실제 픽셀 원화/테마 변형·잠금해제 키프레임·별도 FX를 한 가족으로 준비하고 제품에 연결한다.

## 출처·검증·남은 제약

직접 작성한 벡터 기하 도안이다. 타게임 이미지·영상·음원 사용 없음. `build-preview.py`는 게임 코드를 읽거나 실행하지 않고 SVG/manifest만 만든다. 래스터 아틀라스가 아니므로 alpha/색수 검사를 통과했다고 주장하지 않는다. 정적 XML 구조/48변형 수/출력 파일과 diff를 확인한다. 브라우저 렌더·게임 배경 위 육안·실기기·충돌·게임 테스트·푸시·배포는 미실행이다.

측면은 비교표 수납을 위해70% 표시하며 기본/2배 확대는 비교표 배율이다. 게임 native1x 비교가 아니다. 작은 치수에서 재료 질감·횃불 겹침·벽 이음새와 북남 반전의 광원 방향은 후속 실제 배경 검토 대상이다. 운영0.63과 누적31개 미실행 회귀는 유지한다.
