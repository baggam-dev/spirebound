# 머리 위 대사 통합 화면 시안 v1 — 2026-10-20

사용자 ‘진행하자’로 직전 제안의 머리 위 짧은 대사/점진적 스토리 단서 방향을 진행한다. 이번에는 새 말풍선의 위치·톤을 처음 시각화하며 기존 서사6장면 또는 캐릭터 외형을 다시 승인받지 않는다. 말풍선 화면 디자인 승인 전 runtime에 넣지 않는다.

## 패키지
`overhead-dialogue-v1.png`: 파수꾼/프리즘/군체/칼드/베라/상단벽 대악마의6패널. 기존 저장된 게임 화면을 카메라·어두운 바닥/벽·배치 참고로, 승인 캐릭터 원화를 정체성 참고로 쓴 **imagegen 화면 모형**이다. 실제 브라우저 캡처에 대사가 동작하는 증거가 아니며 현재 런타임 화면을 픽셀 단위 그대로 복제한 결과도 아니다. 예전 저장된 PNG를 읽는 작업만 했고 새 서버/브라우저 QA는 실행하지 않는다.

보드 목표:
- 작은 차콜 판/얇은 회색 선/따뜻한 회백 글씨·최대2줄/짧은 꼬리. 이름은 기존 명패와 분리.
- 칼드/베라는 같은 관문에서 한 명씩 말하는 두 대표 상태. 동시 두 말풍선은 피한다.
- 파수꾼은 침묵, 프리즘은 시스템문, 군체는 들은 경고 모방, 칼드는 명령/베라는 왕좌의 비밀을 암시.
- 대악마는 머리가 위쪽 벽에 걸쳐 있어 말풍선을 화면 안쪽 옆으로 이동해 상단 보스HUD 공간을 확보한다. 아래의 실제 공격공간은 비워 둔다.

## 승인 뒤 구현 기준
UI 판/꼬리/글자는 현재 Canvas/도트폰트로 그려 선명하게 표시한다. 생성 PNG의 문자를 잘라 런타임 글자로 쓰지 않고, 기존 보스 스프라이트/전장/크기를 재생성 이미지로 교체하지 않는다. 생성 시안의 방 크기/원근/임의HUD/보스 비율은 밸런스 변경 대상이 아니다.

실제 머리 앵커는 캐릭터 외형·현재 자세와 HUD 경계를 기준으로 잡는다. 머리 위 작은 체력바와 겹치지 않도록 판/꼬리/체력바를 배치하고, 상단벽에서는 제한 범위 내 옆 위치를 우선한다. 막힌 공간에서 공격 예고를 덮으면서 억지로 대사를 표시하지 않는다. 칼드/베라는 사망순서/상대 생존여부에 맞게 순차 발화하고 군체 분열은 첫등장/최종전멸에만 연결한다.

대사 내용·단서 공개순서·안전한 도입/비차단전환·중단복귀/결과단일성은 docs/title-story-direction-20261020.md 최상단 추가검토를 따른다. 새 정사를 전체 확정한 것으로 확대하지 않는다. PNG가 승인되면 재생·분열/사망순서·구저장/스킵·모바일을 구현 단위로 묶고 새로운 명시 배포 지시 때 검증한다. BGM은 계속 보류.

## 이번 확인 범위
직접 확인: 2열×3행/6종, 어두운 작은 대사판/회백 글자/짧은 꼬리, 침묵/프리즘2줄/군체경고/칼드와베라각1명씩/상단벽옆대사판. 큰 군체도 대사판이 옆으로 이동한 예시다. 보드의 점 개수/말줄임표/‘냐’ 등 생성문자는 픽셀 단계에서 흔들릴 수 있어 실제 문구는 설계의 문자열로 그린다. 생성본의 붉은 상단체력바/미니맵/군체옆 소형체/주인공 자세는 새HUD·전투상태·규모변경이 아니다. 첫6참조호출은도구5개제한으로생성전거부, 참조5개로생성1회성공·재생성없음. 프롬프트/생성원본은 overhead-dialogue-prompt-v1.md에 보존했다.
