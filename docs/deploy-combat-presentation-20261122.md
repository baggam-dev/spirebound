최초 전체940중939통과/1실패는 새3PNG를 전층extra로 요청해 첫층49,896,094B로 기존44MB 예산을 초과한 실제 문제였다. 테스트 예산을 완화하지 않고 실제 스킬 보유/해당 적 방 진입 시 선택 요청하도록 수정했다. 정상 로딩이 늦거나 실패하면 기존 몸체/접점으로 유지한다. 로컬 서버 새3PNG 허용 누락도 수정하고 HTTP 회귀를 추가했다.

통합 도구의 초기 실패는 첫층에 없는 일반 궁수방 조건, 지원 몬스터 입장 교체와 그 계획에 맞지 않는 합성 저장이었다. 지원 계획이 없는 실제 일반방과 그 방의 원래 궁수 식별자를 사용하는 fixture로 수정했다. first~fourth 실패 로그/상태/캡처와 fixture-check.log를 보존했다. 운영 저장 검증을 느슨하게 하지 않았다.

실제 캡처에서 덩치 적의 새 포즈 폭이 기존보다 좁아 보이는 점을 찾아, 높이67/발 위치를 유지하고 가로1.28로 기존 체격에 맞췄다. 보정 후 전신·보행6포즈 native/월드 캡처를 다시 검토했다. 모바일 빌드의 긴 요령은 기존 스크롤을 사용하며 실제 잔여 상태도 확인한다.
