# 스킬 트리·플레이어 효과 개편 검토

상태: 사용자 검토용 제안. runtime 미변경·밸런스 미확정.

## 확인한 현재 구조

- mainSkills는 화염/서리/독/번개/정밀5종이고 최초 mainPanel은5개 모두 표시한다.
- 정밀만 weakpoint/finisher 전용 보조가 있으며 초반 levelChoices는 이 둘이 없으면 약점 추적 후보를 보정한다. 일반 후보는 허용 목록에서 등급별 가중 무작위3개다.
- 메인3레벨 분기(서리는4레벨 추가 성장), 공용 갈래/관통/리듬/연속, 조건이 충족되면 발동하는3개 조합, 별도 궁극기 선택이 있다.
- 근접 오라는 반경90/115/140·초당24/48/72 및3레벨60초마다1회 방어다. 접촉 위험 속으로 접근할 보상이 지속 피해·방어에 치우쳐 있고 순간적인 공격 선택이 잘 드러나지 않는다. 사용 빈도에 대한 계측 검증은 하지 않았다.

## 1. 레벨업 UI

중세 두루마리는 적합하지만 화면 전체를 누런 종이로 덮기보다 어두운 전술서 바탕에 펼친 양피지 카드3장을 추천한다. 선택지는 넓은 가로3열로 유지하고 긴 설명은 접어 둔다. 장식은 가장자리만 쓰며 본문 글자 대비와 모바일 가로 가독성을 우선한다.

상단은 현재 메인·분기·빌드 핵심 태그, 카드는 큰 아이콘/이름/현재→다음레벨/이번 선택으로 바뀌는 행동1문장/핵심 수치 변화/시너지 대상·다음 해금 조건, 하단은 다시뽑기 횟수를 표시한다. 미확정 분기는 카드 상세에서 미리 볼 수 있게 하되 레벨업마다 큰 트리 지도를 열도록 강요하지 않는다. 수치만 긴 기존 설명을 단계별 이득 중심으로 나눈다. 다음 디자인 단계에서 실제 PNG 시안을 제시한다.

## 2. 메인 무작위3종 중1종

5종 중 중복 없이3종을 첫 메인 선택 때 고정 추첨하는 제안이다. 새로고침/저장 재개로 후보를 바꾸지 않도록 run RNG와 후보 저장·선택 검증을 함께 설계한다. 메인을 고른 뒤 다른 메인은 제시하지 않는다. 최초 메인 선택 자체의 재추첨1회는 제안이며 일반 보조 재추첨과 공유할지 별도일지는 미확정이다. 보스 연습의 메인 직접 선택은 일반 도전의 랜덤화와 구분하여 유지하는 것이 적절하다.

기존 저장의 확정 메인을 임의 변경하지 않는다. 메인 미선택 구저장 및 이미 투자한 다른 속성 환급 규칙은 개편 시 버전 이관 대상으로 명시해야 한다.

## 3. 메인별 시너지 성장

정밀의 성공적인 구조는 전용 스킬이 존재한다는 점과 메인의 전투 습관이 전용 보조를 통해 더 강해지는 점이다. 모든 메인에 서로 다른 전용 보조2개와 최종 분기2개를 설계하고, 공용 보조도 메인에 따라 의미가 달라지게 한다. 아래는 미확정 행동 예시다.

| 메인 | 핵심 전투 습관 | 전용 보조 방향 | 기존 공용 보조와의 의미 |
|---|---|---|---|
| 정밀 | 같은 적 집중·강화탄·처형 | 약점 누적 / 저체력 마무리 유지 | 연속·갈래가 주탄 표식을 복제해 무한 강화하지 않게 현재 주탄 제한 유지 |
| 화염 | 느리고 묵직한 첫 적중 폭발 | 폭발 압축 / 화상 누적 후 연소 | 갈래는 군중 폭발, 연속은 후속 폭발, 리듬은 둔한 발사의 공백 보완 |
| 서리 | 중첩 둔화→빙결→파편 | 빙결 도달 / 파편 전파 | 연속은 중첩 보조, 관통은 여러 적 동결 준비 |
| 독 | 누적→가스→처치 확산 | 독 누적 / 가스·처치 확산 | 관통은 감염, 갈래는 감염 대상 확대 |
| 번개 | 직격→전이→주기 천둥 | 집중 방전 / 다수 연결 | 리듬은 직격 빈도, 갈래는 연결 시작점 확대 |

후보를 완전히 정해진 트랙으로 만들기보다3자리 중1자리는 유효한 메인/전용 시너지 후보를 보정하고, 나머지는 공용·보유 강화·새로운 보조가 섞이게 하는 방식을 추천한다. 이미 최대 레벨인 후보는 제외한다. 궁극기5/10레벨 보장 등 기존 중요한 보장은 유지하거나 명시적으로 재설계해야 한다. 각 메인이 반드시 같은 최종 빌드로 수렴하지 않도록 단일 집중/군중 처리/기동 생존의 선택 비용을 남긴다.

조합은 단순 수치 덧셈보다 공격 행동을 바꾸되 재귀 발동을 제한한다. 폭발이 다시 폭발을 낳거나 파편이 파편을 무한 생성하지 않도록 발동원·재발동 간격·1타당 횟수·추가탄 계수를 먼저 정한다. 정확한 피해/중첩/쿨다운 수치는 아직 제안하지 않는다.

## 4. 근접 오라 대체: 자동 요격 참격 권장

계속 피해를 주는 원을 없애고, 적이 가까워지면 가장 가까운 위협 방향으로 짧고 굵은 전방 참격을 자동으로 내는 보조를 제안한다. 접촉 전에 대응할 수 있는 짧은 거리와 재사용 시간을 두며, 새 모바일 조작 버튼은 추가하지 않는다. 공격 범위는 몸 기준 부채꼴이고 벽 너머를 때리지 않는다. 적이 없으면 낭비 발동하지 않으며, 적 진입 때마다 즉시 무한 발동하지 않게 공통 쿨다운을 둔다.

메인별 변형 예시: 화염은 불꽃 참격/화상 보조, 서리는 짧은 둔화·빙결 준비, 독은 근거리 독 분사, 번개는 짧은 전방 방전, 정밀은 약점 대상에 집중 타격. 동일한 원형 오라를 색만 바꾸는 방식이 아니다. 이 근접 보조가 정밀 주탄 표식·서리 파편·독 처치 폭발 등을 무제한 복제하지 않도록 전용 발동원 규칙이 필요하다.

성장 방향은 범위만 늘리지 말고 '단발 위력/발동 간격/돌파 후 생존'의 분기를 검토한다. 기존3레벨 자동 방어막은 근접 공격과 무관한 보너스이므로 수호 계열 선택으로 분리하는 것을 추천한다. 기본적으로 강제 넉백·긴 경직·무료 무적은 제안하지 않는다. 보스를 일방적으로 봉쇄하지 않아야 한다.

대안인 점멸 후 참격은 적극적 재미가 있으나 유일한 생존 이동기를 공격용으로 강요할 수 있어 기본안보다 우선하지 않는다.

## 작업 순서와 승인 경계

사용자 최신 순서: 플레이어 스킬 트리+스킬 효과 → 적 공격 효과 → 피격·사망/보스 연출. 직전 인계의 피격·사망 우선보다 이 순서가 최신이다.

이번은 코드 확인과 설계 검토만이다. 방향 합의 후 UI PNG 시안과 메인별 성장표를 먼저 확정하고, 메인 후보/저장 구조·전용 보조·오라 대체를 구현한 뒤 확정된 공격에 맞춰 플레이어 효과를 제작한다. 시안 없이 즉시 구현하라는 이전 예외는 '모든 캐릭터 걷기' 범위였으며 새 스킬 UI/게임 규칙 승인으로 확대하지 않는다. 테스트·원격 푸시·배포·공개 검증은 새 명시 배포 지시 후 진행한다.
