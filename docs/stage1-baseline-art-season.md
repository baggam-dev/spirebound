## 아트 방향 비교와 임시 권장

비교판은 같은 **합성 장면**에 영웅·적·타일·탄환·위험 표식을 동일 위치로 놓고 팔레트만 바꿨다. 실제 게임 스크린샷이나 확정 에셋이 아니다. 패널 A `재의 성채`는 기존 1~7층 석조와 가깝고, C `타락한 왕실`은 8층의 남보라/황동, B `지옥 현무암`은 9·10층 검붉은 균열/불씨를 제안한다.

- **임시 권장:** A(1~7층) → C(8층) → B(9·10층). 픽셀 격자·줄눈·위쪽에서 오는 빛과 캐릭터의 금발/활 실루엣은 공통으로 유지한다. 층이 깊어질수록 배경 채도는 낮추고 위험 예고/화살은 더 또렷하게 분리한다.
- B는 바닥까지 선명한 빨강으로 채우지 않는다. 주황 불씨는 지형/화염, 자주는 악마 마법, 청색은 빙결/안전 구분에 남겨 실제 전투 정보가 보이게 한다. 색만으로 위험을 구분하지 않고 예고 형태/시간·소리도 사용한다.
- 최종 선택은 1층 일반방·8층 왕실방·9층 일반방 및 9층 보스 전투의 **실제 960×540 캡처와 모바일 크기**에 같은 규칙을 적용해 결정한다. 이 비교판만으로 사용자 취향이나 실제 기기 가독성을 확인한 것으로 간주하지 않는다. 다음 기능(군단장)에서는 임시 팔레트만 참고하고, 대량 아트 제작은 이후 세로 조각 단계에서 한다.

## 공개 랭킹과 기존 저장의 경계

현재 `src/ranking/ranking.js`는 BETA-1/ranking-v1과 ASCENT-1/ranking-v2를 상수로 정의하고 저장 검증에서 해당 캠페인의 현재 규칙/시즌과 **정확히 일치**해야 한다. 따라서 상수만 바꾸면 기존 저장 자체가 거절될 수 있다. `api/ranking_api.py`의 DB는 과거 시즌을 조회할 수 있지만 새 도전/기록 제출 허용은 현재 활성 시즌 2개만 지원하며, `ranking-ui.js`도 시즌 버튼 2개를 고정해 둔다. 새 빌드 ID도 서버 `MAIN_SKILLS`에 없다. 시즌 전환을 단순 문자열 교체로 처리할 수 없다.

**권장 정책(아직 구현 전):**

1. 9·10층 보스·9층 적은 ASCENT-1의 비교 가능성을 바꾸므로 해당 변경을 공개할 때 새 10층 시즌/규칙으로 시작한다. 6~8층 출현표나 새 스킬이 8층에도 적용되면 BETA-1도 새 8층 시즌이 필요하다. 이름·버전 번호는 실제 구현 때 확정한다. 순수 외형 변경만이면 기존 시즌 유지 가능하다.
2. 기존 BETA-1/ASCENT-1 기록은 **읽기 전용 과거 시즌 목록**으로 남긴다. 새 규칙의 점수를 옛 목록에 섞거나 자동으로 이전하지 않는다. 이미 등록된 기록의 동일 요청 재시도는 현 API 정책상 영수증을 반환하지만, 종료 후 미등록 옛 도전의 새 제출은 실패한다는 사실을 UI에 설명한다.
3. 기존 저장은 이전 규칙 ID와 플레이 상태를 보존하여 **로컬 이어하기**가 가능하게 하고, 변경된 게임 규칙으로 이어간 옛 도전은 새 시즌 온라인 등록에서 제외한다. 버전 검증 전에 저장을 버리지 않도록 `storage.js`/`validateRanking`의 구버전 허용·이관 순서를 고친다. 새 도전만 새 시즌 등록을 시작한다.
4. 서버는 시즌별 규칙/캠페인/활성 여부를 분리하고, UI는 현행·과거 시즌을 조회 가능하게 한다. 클라이언트/서버의 점수·도전 시작·제출 거부 기준, 닉네임/쿠키 식별, 배포 롤백과 기존 저장 재개를 로컬 격리 DB에서 검증한 뒤 공개 전환한다. 실제 운영 DB 기록은 시험 제출하지 않는다.

이 문서는 **군단장 변경 전**의 고정 조건 기준선과 임시 아트/시즌 제안이다. 실제 군단장 전투와 신규 시즌 작업은 후속 `commander-stage1.md`에 기록한다. 실제 피격률과 아트 최종 선택은 이 준비 단계에서 확인하지 못했다.
