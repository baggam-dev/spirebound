# 랭킹 규칙 v1 — 1단계 설계

상태: 베타 기준. 2단계 로컬 점수, 3단계 서버 API, 4단계 온라인 시작·닉네임 등록·RANK 화면 연결까지 구현했다. 5단계 운영·HTTPS 점검이 남아 있다.
목표: 8층 모르도를 처치하고 1층으로 탈출한 기록으로 경쟁한다. 빠른 귀환과 추가 탐험 모두 점수에 기여하도록 한다.

## 등록 자격

- 일반 도전에서 모르도 처치 → 열쇠 획득 → 1층 탈출까지 성공한 기록만 등록한다. 사망·중도 종료·보스 테스트는 제외한다.
- 랭킹 기능 도입 이후 시작한 도전만 등록한다. 기존 저장과 과거 로컬 기록은 계속 플레이·조회할 수 있지만 점수를 소급 등록하지 않는다.
- 저장 후 이어하기를 허용한다. 같은 지도 재도전도 허용하되 새 runId로 시작하며 시드를 기록한다.
- 도전 시작 시 seasonId, rulesVersion, 게임 버전을 고정한다. 시즌 종료 이후 완주한 도전은 개인 기록에만 남긴다.
- 네트워크 실패 시 결과와 등록 요청을 로컬에 보관하여 재시도한다. 종료된 시즌에는 재시도로 새 기록을 등록하지 않는다. 이미 접수된 요청은 기존 성공 결과를 돌려준다.

## 점수 공식

총점 = 탈출 10,000 + 처치 + 탐험 + 시간. 최대 22,000점.

| 항목 | 계산 | 상한 |
| --- | --- | --- |
| 탈출 | 등록 자격을 충족하면 10,000점 | 10,000 |
| 처치 | 유효 처치 수 × 10점 | 4,000 |
| 탐험 | floor(2,000 × 고유 방문 방 수 / 생성된 전체 방 수) | 2,000 |
| 시간 | max(0, 6,000 − floor(실제 플레이 밀리초 / 1,000) × 2) | 6,000 |

- 시간은 현재 elapsed와 같이 실제 시뮬레이션이 진행되는 시간이다. 일시정지·선택 화면·백그라운드·저장 종료 시간은 제외한다. 탈출 시 한 번 밀리초 정수로 확정하고 점수와 동점 판정에서 동일한 값을 쓴다.
- 50분부터 시간 보너스는 0점이다. 장시간 완주도 탈출·처치·탐험 점수를 받는다.
- 유효 처치: 최초 편성, 유한한 상자·이벤트 전투, 하강 시작 시 추가 편성된 적. 보스·정예도 각 1처치이며 별도 가산점은 없다.
- 전투 중 소환몹과 분열 자식은 제외한다. 분열 전 원본은 1처치만 인정한다. 같은 적을 여러 번 집계하지 않도록 전역 식별자(층·방·생성 차수·적 ID)를 사용한다.
- 하강에 새로 추가된 적은 별개 처치 대상이다. 등반에서 살아남은 동일 적은 새 대상으로 복제하지 않는다.
- 탐험은 생성된 모든 방을 대상으로 한다. 시작방 포함, 등반·하강 합쳐 방당 한 번만 인정한다. 미니맵 공개만으로는 방문으로 인정하지 않는다.
- 피해량·남은 체력·유물 개수·레벨은 점수에 넣지 않는다. 체력 증가·회복 빌드와 보상 운에 따른 추가 편향을 피한다.
- 처치 400회 상한과 50분 시간 기준은 베타 시작값이다. 실제 완주 기록을 수집한 후 다음 시즌에서 조정한다.

### 계산 예시

| 기록 | 탈출 | 처치 | 탐험 | 시간 | 총점 |
| --- | --- | --- | --- | --- | --- |
| 20분, 180처치, 60/80방 | 10,000 | 1,800 | 1,500 | 3,600 | 16,900 |
| 30분, 300처치, 80/80방 | 10,000 | 3,000 | 2,000 | 2,400 | 17,400 |
| 50분, 450처치, 80/80방 | 10,000 | 4,000 | 2,000 | 0 | 16,000 |

## 순위·참가자

- 정렬: 총점 내림차순 → 플레이 시간(ms) 오름차순 → 서버 최초 접수 시각 오름차순 → 기록 ID 오름차순. 순위는 1, 2, 3처럼 개별 부여한다.
- 시즌별 참가자 최고 기록 1개만 상위 100위에 노출한다. 나머지 성공 기록은 개인 기록으로 남긴다. 서버는 위 정렬 기준으로 최고 기록을 선택한다.
- 초기 베타는 로그인 없이 서버가 발급한 익명 참가자 식별자를 사용한다. 닉네임은 식별자가 아니며 중복을 허용한다.
- 브라우저·기기를 바꾸거나 식별 정보를 지우면 별도 참가자가 된다. 따라서 베타에서는 실제 사람당 1개 기록을 보장하지 않으며, 경쟁 규모가 커지면 계정 연동을 별도 도입한다.
- runId당 한 번만 등록한다. 재전송으로 점수·이름·서버 접수 시각을 갱신하지 않는다.

## 닉네임

- 탈출 결과 화면에서 점수 내역을 확인한 뒤 이름을 입력한다. 등록은 선택 사항이며 건너뛰어도 개인 결과는 저장한다.
- 앞뒤 공백 제거 및 Unicode NFC 정규화 후 한글 완성형·영문·숫자·밑줄만 2~12자로 허용한다. 공백·제어문자·HTML·이모지는 허용하지 않는다.
- 금칙어 및 운영자 사칭 이름은 서버에서 거부하고 수정 안내를 표시한다. 구체적인 금칙어 목록은 서버 구현 단계의 설정으로 관리한다.
- 화면에는 항상 텍스트로 출력한다. 닉네임 수정은 다음 기록 등록부터 적용하고 이전 기록은 바꾸지 않는다.

## 시즌·검증

- 최초 시즌은 BETA-1, 점수 규칙은 ranking-v1. 일정 기반 자동 초기화는 도입하지 않고 운영자가 시즌을 전환한다.
- 점수 공식·전투 난이도·지도 생성·성장 보상 또는 점수에 영향을 주는 버그 수정 시 새 시즌으로 분리한다. 외형·문구 수정은 같은 시즌을 유지한다.
- 종료 시즌은 읽기 전용 보관한다. 구버전 클라이언트와 서버가 허용하는 게임 버전 범위는 서버가 관리한다.
- 서버가 원시 집계값으로 점수를 다시 계산한다. 클라이언트가 보낸 총점을 그대로 신뢰하지 않는다.
- 자격·버전·자료형·유한 수치·고유 이벤트·방문 수 범위·중복 도전·요청 빈도를 검증한다. 의심 기록은 공개 순위에서 보류한다.
- 클라이언트 집계 검증만으로 조작 방지가 완성되지는 않는다. 서버 발급 도전 정보와 검증 가능한 이벤트 수집은 2~3단계에서 설계하고, 완전한 실행 재현 검증은 별도 범위로 둔다.

## 현재 코드와 2단계 인계

- engine.js newRun: runId, seed, elapsed, kills와 생성된 지도가 이미 존재한다.
- simulation.js: 소환몹은 일반 kills 집계에서 제외되지만, 랭킹은 별도 유효 처치 이벤트로 관리해야 한다. 분열·하강 편성과 저장 재개까지 식별자를 유지한다.
- 각 방의 seen을 실제 입장 시 고유 방문 집합에 반영한다. 전체 방 수는 도전 시작 시 고정한다.
- game.js finish / resultPanel: 탈출 확정 시 점수 스냅샷을 만들고 항목별 점수를 표시할 위치다.
- storage.js: 도전 저장 및 완료 기록에 랭킹 버전·집계·결과 스냅샷을 추가하고 기존 저장 호환성을 보존한다.
- 2단계 검증: 점수 경계값·시간 반올림·중복 처치·소환/분열 제외·하강 신규 편성·재입장·저장 재개·과거 저장 제외·보스 테스트 제외.

1단계는 규칙 문서만 추가했다. 2단계 구현 및 검증은 ranking-stage2.md에 기록한다.
