# 양대 앱스토어 출시 품질 점검 — 2026-10-06

## 판정

**현재는 공개 웹 베타를 다듬은 단계이며, Apple App Store/Google Play의 정식 출시 후보로 판정할 증거가 부족하다.** 이는 게임의 재미가 부족하다는 확정 평가나 스토어 심사 불합격 예측이 아니다. 실제 iPhone/Android 앱 빌드와 사람 플레이의 데이터가 없어서 출시 품질을 입증하지 못한 상태다. 사용자는 당분간 운영 개선보다 게임 품질 개선을 우선한다.

## 게임 품질 우선 작업 순서

1. **실제 플레이 기준선.** 신규 플레이어 3~5명이 기본/확장 캠페인을 최소 한 번씩 독립적으로 플레이하도록 하고 첫 10분 이탈, 첫 사망 원인, 기술 선택 이해, 6층 이후 반복감, 9·10층 예고/회피, 완료·재도전 의사를 기록한다. 동의를 얻은 구체적 재현 사례만 이슈화하고 개인 원시 기록은 저장소에 넣지 않는다. 목표는 수치보다 반복되는 치명 문제 0건과 우선순위가 명확한 문제 목록이다.
2. **실기기 전투 UX.** iPhone과 Android 각각 실제 기기로 가로 HUD/미니맵/터치 버튼, 화면 회전, 앱 전환 뒤 재개, 스킬 선택, 보스 탄막·피격 정보, 음량·진동 필요성을 확인한다. 특히 모바일 가로의 작은 수치를 먼저 개선 후보로 본다. 목표 기기와 최소 OS는 빌드 전 확정한다.
3. **전투/연출 완성도.** 플레이 테스트에서 반복 재현된 불공정 피격·단조로운 층/빌드·보스 체력·예고 전달을 수정한다. 영웅/적/환경/스킬의 픽셀 크기·대비·색 언어를 같은 실기기 화면에서 통일하고, 효과음이 없는/꺼진 상태에서도 위험을 읽을 수 있게 한다. 이미 끝낸 아트·성능 개선을 다시 구현하지 않는다.
4. **모바일 고부하 안정성.** 두 기기에서 30분 이상 실제 전투와 9·10층 탄막을 포함해 프레임 간격 p95/p99, 터치 지연, 메모리, 발열, 저장 손실을 측정한다. 목표치와 지원 기기를 정한 뒤 치명적 진행 손실 0을 출시 게이트로 둔다.
5. **그 다음 앱 패키징/스토어 심사.** iOS/Android 빌드·내부 배포를 만들어 실제 앱 컨테이너에서 저장/소리/일시정지/뒤로가기/네트워크 실패를 재검증한다. 앱 아이콘·스크린샷·개인정보/지원 안내·연령 등급/데이터 신고와 스토어 설명은 제출 단계에서 마무리한다. 서버 외부 백업·알림은 이번 게임 품질 우선 작업의 다음 단위가 아니다.

## 플랫폼별 별도 게이트

- **Apple:** 심사 지침 2.1은 완성된 메타데이터·작동 URL·실기기 안정성을 요구한다. 4.2는 재포장 웹사이트를 넘는 기능/콘텐츠/앱다운 UI와 지속적 오락 가치를 요구한다. Spirebound의 게임 콘텐츠가 풍부하다는 점은 긍정적이지만, 순수 웹뷰 포장의 통과를 보장하지 않는다. iOS 앱 빌드와 TestFlight 기기 검증 후 판단한다. Apple은 iOS 앱 개인정보 처리방침 URL과 데이터 처리 공개를 요구한다. 2026년 4월부터 제출 앱은 iOS 26 SDK 이상 빌드가 필요하다.
- **Google Play:** 현재 신규 앱/업데이트 대상 API는 Android 16(API 36) 이상이다. 기능적·흥미로운 경험과 안정성이 요구되며, 데이터 보안 양식/개인정보 처리방침을 제출한다. 2023-11-13 이후 생성한 개인 개발자 계정이라면 12명 이상이 14일 연속 참여하는 비공개 테스트 후 프로덕션 접근 신청이 필요하다. 계정 종류/생성일은 미확인이다.
- **공통:** 실제 승인 여부는 각 스토어 심사와 최종 앱 바이너리·메타데이터에 달려 있다. 현재 저장소에 앱 프로젝트가 없으므로 출시 가능 시점을 추정하지 않는다. 개인정보/공개 랭킹 기록 문의 경로는 제출 전 남은 작업이며, 지금은 게임 품질 검증을 먼저 한다.
