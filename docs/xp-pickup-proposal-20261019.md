# 경험치 바닥 드롭·흡수 방식 검토 — 2026-10-19

상태: 사용자 아이디어 검토안. 구현/디자인/배포 승인 전. 현재 미배포 비전투6종 구현 c7ee626은 그대로 보존하며 이 제안은 별도 변경이다.

## 판단

추천한다. 처치→흩어짐→접근→흡수→성장의 감각을 연결하고, 정수 자석을 전투 중 성장 시점과 이동 동선을 바꾸는 유물로 만들 수 있다. 정예/보스 보상이 터지고 모이는 순간도 강화할 수 있다. 다만 경험치를 전부 손으로 청소하도록 강제하면 이미 짧게 만든 초반 방 진행과 충돌한다. 핵심은 전투 중 수집에 의미를 주면서 전투 후 반복 왕복을 줄이는 것이다.

이 문서는 ‘몹 클리어’를 **각 몬스터 처치 시** 드롭으로 해석한다. 방 전체 클리어 때 한꺼번에 지급하는 방식과 구별한다. 둘은 아직 사용자 선택으로 확정하지 않았다.

## 실제 코드 기준

- `src/game/simulation.js`: 상승 중(`!s.key`) 비보스 처치 시 `e.xpReward??12` 즉시 지급. 소환체는 앞에서 건너뛴다. 보스방 완료는 경험치45를 별도로 지급한다. 일반/정예의 실제 xpReward와 보스 완료 조건을 그대로 존중해야 한다.
- 경험치 임계값은 `xpRequired(level)`로 처리하고 pendingLevels/levelQueue에 선택을 예약한다. 드롭을 만들 때가 아니라 **수집 확정 때** 이 경로로 경험치를 지급하는 구조를 제안한다.
- `src/progression/essences.js`: 정수는 실제 능력치 보상5종이며 기본 반경30+relicStat('pickup')에서 벽을 검사해 수집한다. 경험치와 같은 보상이 아니다.
- `src/progression/relics.js`의 정수 자석은 pickup+70. 현재 정수 기본30→100px이며 경험치에는 적용되지 않는다. 우선 경험치에도 같은 pickup 보너스를 공유하고 이름/설명을 ‘수집 자석 · 경험치·정수 획득 반경 +70’처럼 명확히 바꾸는 안을 제안한다. 최종 이름은 미확정이다.

## 추천 첫 버전

1. **기존 경험치 총량 유지.** 지급만 즉시 획득에서 바닥 드롭→수집 확정으로 옮긴다. 경험치 곡선/기본12·xpReward/보스45·정예 보상 확률·정수 드롭률을 동시에 바꾸지 않는다. 체감 수집부터 분리해서 볼 수 있다.
2. **작은 경험치 가루/구체와 큰 정수를 구분.** XP는 작고 옅은 백색/청백색 둥근 가루 묶음, 기존 능력치 정수는 큰 마름모 형태와5색·라벨을 유지한다. 적탄과 구별하고 바닥 위험 예고를 가리지 않는다. 외형 이름/색은 시안 승인 전 미확정이다.
3. **반경 안에 들어오면 짧게 끌려와 흡수.** 기존 pickup+70을 공통 적용하는 안을 우선한다. 실제 기본 반경은 정수의 기존30px부터 검토하고, 모바일에서 답답하면 XP 기본 범위를 별도로 조정한다. 희귀 정수의 반경까지 무조건 키우지는 않는다. 장벽 너머/방 밖 보상을 몰래 수집하지 않으며, 벽 모서리에 멈추는 문제가 생기지 않게 접근 가능한 위치에 드롭한다.
4. **전투 중 직접 수집, 방 출발 때 남은 XP만 회수.** 방을 정리하고 실제 문/계단으로 이동이 성공할 때 남은 경험치를 한 번만 빠르게 회수하는 방식을 추천한다. 정수·미래 재화까지 자동 회수하는 규칙으로 확대하지 않는다. 자석은 전투 중 더 안전하고 빠른 레벨업을 돕고, 출발 전 바닥 청소 때문에 진행 속도가 느려지는 것을 막는다. 이 보조 규칙은 제안이며 사용자 확정 전이다.
5. **시간이 지나 경험치가 사라지지 않게 한다.** 수집하지 않은 XP는 방 상태/저장에 남기거나 위 출발 회수 규칙으로 정리한다. 재진입/이어하기 시 사라지거나 두 번 받지 않아야 한다. 보상 수집을 위해 공격을 피하는 선택과, 보상 자체를 잃는 불쾌함은 구분한다.

## 정예·보스의 작은 보상 폭발

일반 적은 작은1~3묶음 정도로 간결하게, 정예/보스는 여러 가루 조각이 짧게 밖으로 튄 뒤 바닥에 놓이고 빠르게 흡수되는 장면을 추천한다. 시각 조각 수와 실제 경험치 데이터 개수는 분리한다. 보스는 많은 조각처럼 보여도 합계45를 넘지 않게 몇 개 보상 묶음으로 관리할 수 있다. 숫자마다 보상 텍스트를 띄우거나 소리를 겹쳐 재생하지 않고, 짧은 연속 흡수음/한 번의 성장 반응으로 마무리한다.

현재 정수는 희귀 능력치 보상이므로 ‘폭발을 화려하게 만들기 위해’ 드롭 개수를 늘리지는 않는다. 기존 정수 지급은 눈에 띄게 강조하고 XP 가루가 그 주변에 터지도록 제안한다. 보스 보상 선택창/다음 층 상호작용을 강제로 기다리게 하지 않는다.

## 기술·진행 규칙

- 드롭 생성과 시각 조각은 결정적으로 배치하고 기존 전투/전리품 RNG를 소비하지 않는다. 흩어짐 범위는 방/벽/문과 접근 가능한 바닥 안으로 제한한다.
- 많은 적이 죽어도 가까운 XP 묶음은 값이 보존되게 합치거나 논리 오브젝트 상한을 둔다. 상한 때문에 경험치 총량이 없어지면 안 된다.
- 죽음 판정에서만 생성하고 피격/사망 그림자·슬라임 분열 연출·소환체·보스 부위 전환에서 중복 생성하지 않는다. 현재 소환체/하강 무경험치 규칙 유지.
- 방별 드롭 ID·위치·값과 회수 상태를 저장/검증하고 경험치 원장 합계를 보존한다. 오래된 저장은 기존 경험치를 빼앗거나 지난 적의 드롭을 다시 만들지 않는 방향으로 이관한다.
- 수집 즉시 pendingLevels/levelQueue를 기존 성장 경로와 일관되게 갱신한다. 보스/정예 보상 수집 때문에 같은 선택창이 중복되거나 수집이 여러 레벨을 건너뛰지 않도록 한다.
- 정지 중 이동/흡수/경험치가 진행되지 않고, 효과 줄이기에서도 작은 보상 본체는 보인다. 경험치 배경 가루와 실제 수집 가능 드롭을 혼동시키지 않는다.

## 미래 재화

장기적으로 공통 ‘바닥 보상’의 종류를 XP/정수/재화로 확장할 여지는 있다. 하지만 첫 버전에 재화까지 넣지는 않는 것을 추천한다. 재화의 사용처(원정 중 상점인지 원정 밖 성장인지)가 먼저 정해져야 가치·총량·희귀도·자동 회수 규칙을 설계할 수 있다. XP는 성장, 정수는 능력치 보너스, 재화는 소비 선택이라는 역할을 나누면 세 보상을 수집하는 이유가 선명해진다.

## 다음 단계

먼저 직접 수집/출발 시 남은XP 회수 정책과 경험치 외형 방향을 확정한다. 이후 일반/정예/보스 드롭·자석 흡수·희귀 정수 구분을 한 장의 패키지 시안으로 보여주고 승인 후 구현한다. 현재는 검토 문서만 작성하며 runtime/배포 자산은 수정하지 않았다. 테스트/QA·서버·원격푸시·배포·공개 확인도 하지 않았다.
